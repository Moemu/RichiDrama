# 协作保存与关闭入口验收

## 问题与修改

在隔离环境中拒绝 WebSocket 握手，保留普通 HTTP。第 8 集原稿为空时，输入剧本并点击“保存当前集”，旧版本会清空输入，却提示“剧本已保存”。协作文本尚未同步，普通保存请求已过滤该字段，随后刷新读取了数据库旧值。

项目写请求现在先等待已有文本保存。尚未同步的文本通过现有、带鉴权的 HTTP 协作接口确认后，才继续业务请求。HTTP 失败时请求失败，保留草稿。页面刷新延后至草稿已保存；绑定指令恢复仍未确认的本地输入。普通项目的原保存路径保持不变。

负责人可从“成员与设置 → 项目成员 → 关闭协作”关闭协作。确认框说明访问权限变化；当前页面先保存文本。关闭请求期间新输入的草稿不会被清理。关闭后禁用成员管理、分集成员分配及负责人转让入口，提供重新启用入口。

正式 Nginx 配置的 `/api/` 增加 WebSocket Upgrade 与 Connection 转发头。配置尚未应用到线上。本机未运行 Nginx，Docker 引擎也未启动，未执行 `nginx -t`；部署时仍需检查实际加载配置并验证握手。

## 兼容范围与消费者检查

| 范围 | 覆盖结果 |
| --- | --- |
| 普通保存与协作保存 | 检查 drama API、projectRequestSync、useProjectCollaboration、协作文本 HTTP 路由和权限；所有当前项目的写请求统一等待文本确认，文本接口自身排除，避免递归。 |
| 剧本、梗概、分镜及资源文本 | 检索 `hasPendingProjectText`、`v-project-text`、`useProjectTextModel`；保留协作文本与普通字段的现有分工。自动化检查保存确认、失败重试、项目切换和指令刷新。 |
| 协作栏页面 | FilmCreate、DramaDetail、DramaCanvas、FreeCreate 项目模式、MediaLibrary 项目模式均检查。 |
| 身份与访问 | projectAccessService 的详情、批量列表、项目 ID 过滤统一排除已关闭项目的成员。关闭后现有 WebSocket 撤销访问。JWT、Cookie 和账户资料格式不变。 |
| 媒体、生成及历史任务 | 检索所有 `project_collaboration` 消费者。保留协作历史行，使媒体、任务、生成列表的历史归属保护仍生效；关闭不会退回原作者的私有访问兜底。原任务、账本及本地媒体路径不改写。 |
| 刷新与重启 | 覆盖关闭后的读取、普通保存、重新启用、版本递增及旧 Yjs 文本被拒绝；历史私有项目和已存在任务仍可读取。 |

迁移只新增 `disabled_at`，默认 NULL，可重复执行。历史项目不会自动关闭。只有负责人明确执行关闭操作的项目启用关闭行为。未操作的历史项目、分集、媒体、任务和账本全部排除。重新启用保留成员名单与递增版本，不删除协作文档和操作记录。

## 验证结果

- 后端完整测试：444 项通过。HTTP / WebSocket 集成覆盖文本持久化、权限撤销、幂等关闭、重启、重新启用、旧稿冲突、媒体和任务访问；供应商调用次数未增加。
- 前端完整测试：190 项通过。生产构建通过，保留原有大包提示。
- Codex 内置浏览器：`1280×720`、`1440×900`、`1920×1080` 检查上述五个页面。剧本和成员设置检查底部操作可达；画布通过平移到达编辑与保存按钮；素材库与空分镜工作台检查空状态及导航。另在 `390×844` 检查关闭确认框。
- 断线保存后刷新仍有正文。注入 HTTP 503 后仅显示一次错误，正文保留；取消故障后重试成功。
- 关闭前的新梗概已保存。关闭状态刷新后保留；普通剧本保存、后端重启后的读取、重新启用及恢复 WebSocket 后的保存通过。
- 画布剧本保存通过。只读核对隔离数据库：仍有 8 集，第 1–7 集原文不变，第 8 集为最后确认保存的文本。

浏览器使用独立数据库和无供应商配置的本地 HTTP 服务；禁止生成及付费路由。未修改生产数据，未发起真实 AI 调用，未执行线上配置重载或部署。
