# 分集保存安全修复

## 原因与修复

旧保存接口按集号更新，并将请求中遗漏的分集标为删除。编辑页又会解析正文中的多个集标题，从第一集重新编号。这两个行为组合后，保存后续集可能覆盖前面的集。

新增 `PUT /api/v1/dramas/:id/episode-edits`，明确区分 append、update、delete：

- append 在事务内分配新集号，包含已删除集的最大编号，不复用历史身份。
- update 只更新指定 ID 的标题和正文。比较读取时的原文，冲突返回 409。
- delete 只删除指定 ID，并检查读取时的更新时间。

已有项目保存当前集时，不再按正文标题拆集。新项目仍支持拆集。新增分集后，使用后端返回的 ID 选中新集。

## 消费者检查

已检索前端、后端和测试中的分集保存与生成调用。

| 路径 | 结果 |
| --- | --- |
| FilmCreate 当前集保存 | 单集 ID 更新，检查原文 |
| FilmCreate 新建、小说导入、模板导入 | 追加新集 |
| DramaDetail 新增、批量导入、删除 | 显式追加或单集删除 |
| 画布新增与剧本保存 | 显式追加或单集更新 |
| AI 故事生成 | 新增 story/append 路由，返回实际集号和 ID |
| 批量导入弹窗 | 等待保存成功；失败保留预览并显示错误 |
| 项目导入、工具创建项目 | 创建新项目，不覆盖已有项目分集 |
| 分镜替换 | 已有快照检查和事务保护，本次未修改 |

## 兼容范围

新行为仅由新版页面的显式操作或新接口启用。未修改历史记录、数据库结构、媒体文件和账本，也未执行自动清理或恢复。

旧分集保存接口与旧故事生成接口保留原有合约。旧客户端不自动获得新保护。发布时需要同时更新前后端，并刷新已打开的旧页面。新页面请求新路由；连接旧后端时失败，不退回危险的整表保存。
