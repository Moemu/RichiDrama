# 生成链路、计费与租户隔离修复方案

## 目标与边界

本次只在现有 API、历史数据和计费账本可读取的前提下实施。禁止直接调用供应商 API，禁止批量修改历史余额、历史授权或历史媒体。现有用户同属一个项目组，迁移把全部用户安全归入“默认项目组”，不改变项目、余额、账本或任务归属；历史 `tenant_id` 保持为空以维持原有读取语义。

## 发现与优先级

### P0：先消除资金冻结与重复冻结

1. 图像、工具、视频与 Omni 的请求必须要求客户端幂等键；后端不得再以时间或随机数兜底。缺少键返回 400，不创建任务、不冻结额度。
2. 所有失败入口（配置缺失、用户取消、进程重启回收、异步任务失败）必须调用同一授权释放函数。释放是幂等的，已经结算或已经释放的授权不重复写账。
3. 多图提交的授权与结算 usage 使用真实图片数量；测试覆盖 1 张和多张。

### P1：让慢任务可解释、可恢复、可度量

本地历史基线（只读，2026-08-18）：59 条视频任务中 25 条完成，完成任务平均总耗时 216.2 秒、最大 489.5 秒；2 条已完成超分平均 238.8 秒，1 条已完成插帧 293.3 秒。后处理本身就可能超过原始生成，应单列展示，不能把最终 `completed_at - created_at` 误认为供应商生成时间。

视频任务使用持久化阶段状态：`queued → provider_submitted → provider_processing → media_persisting → upscale_pending/upscaling → interpolation_pending/interpolating → archiving → completed`。每个阶段记录开始时间、最近心跳、结束时间、供应商请求 ID、重试次数和可读状态说明。

优化策略：

- 浏览器任务状态轮询采用前台 4 秒、后台暂停并在可见时恢复；服务端不在 HTTP 请求中长轮询。供应商轮询仍由后台服务持久化处理，不能因用户切换标签中断。
- 提交后先持久化任务与供应商请求 ID；后处理只在原片本地可读后排队，超分与插帧分别独立计时。
- 记录 `queue_ms/provider_ms/persist_ms/upscale_ms/interpolation_ms/archive_ms/total_ms`，从本地日志和运营 API 聚合 p50/p95；线上日志只读补充，不触发生成。
- UI 使用阶段步骤条和“已耗时/最后更新/可重试阶段”，不把慢任务误报为失败；状态读取连续失败后变为 `unknown` 并提供手动刷新。

### P1：多租户组与分组计费

新增以下前向兼容表：

| 表 | 关键字段 | 作用 |
| --- | --- | --- |
| `tenants` | `id, name, status` | 租户/工作组主体 |
| `tenant_memberships` | `tenant_id, user_id, role` | 用户只属于一个启用租户（初始可为空，走兼容全局配置） |
| `tenant_ai_config_bindings` | `tenant_id, ai_config_id, service_type` | 绑定现有受保护的 API 配置，不复制密钥 |
| `tenant_sd2_config_bindings` | `tenant_id, ai_config_id` | 绑定现有 SD2 认证配置，不复制密钥 |
| `tenant_price_book_bindings` | `tenant_id, price_book_id, active_at` | 每组共享一个生效价目表 |

请求鉴权后解析 `tenant_context`。模型、SD2、计价、授权、账本和任务均写入 `tenant_id` 与“配置/价目快照版本”；旧用户 `tenant_id IS NULL` 保持当前逻辑。管理员可以创建租户、录入组配置、绑定成员、激活价目表；创作用户只能读取自己的租户可用模型，永不返回密钥。实际执行链路必须把 `tenant_id` 写入图片/视频/Omni 视频和异步任务记录，并在后台恢复、轮询及最终供应商调用时以该记录选择组内配置；不能只在创建页筛选模型后又回退为全局默认配置。

### P1：价目表与外部生图模型

线上只读配置核验确认目标模型键为 `gpt-image-2`（provider `geeknow`，线上 image 与 storyboard_image 的默认模型）。迁移向全局已发布价目表新增 `image` 和 `storyboard_image` 的 `gpt-image-2` 项，每张 40 积分；不覆盖已有同键项，也不复制线上密钥或端点到本地。

### P1：管理员与创作账号隔离

保留现有 `users` 以免破坏 JWT 和历史外键，新增最小权限模型：`creator`、`tenant_admin`、`platform_admin`。平台管理员账号单独创建并设置 `is_console_account=1`；创作账号不得访问 `/admin/*`，且产品导航不渲染运营入口。后端路由以服务端会话角色和权限为唯一事实来源；前端 `localStorage` 只作展示缓存，收到 401/403 时清理缓存并跳转无权限页。

## 实施顺序

1. 审计并修复 P0，增加重复提交、取消、重启回收、配置缺失、多图计费测试。
2. 增加阶段时间线、日志结构化字段与运营读取 API；实现前台阶段可视化与未知状态恢复。
3. 新增租户表、兼容迁移、服务端租户上下文、配置/SD2/价目解析及运营配置页。
4. 增加管理员隔离和路由权限；补充租户越权与密钥不泄露测试。
5. 接入确认后的 40 积分/张模型价目项并验证授权/结算。
6. 提取可见性敏感轮询 composable、处理关键静默错误、清理搜索定时器。

## 验收

- 后端：P0 单元与 HTTP 集成测试；重启后历史任务和媒体仍可读取；不得重复冻结或扣费。
- 前端：测试、构建，内置浏览器在 1280×720、1440×900、1920×1080 验证登录、创作、阶段状态、余额反馈、运营权限与纵向滚动。
- 本地仅模拟/读取，不调用供应商生成，不产生真实计费；不提交或推送。

## 本次实施核验记录

- 默认项目组保留历史全局价目按模型解析；新建但未配置的项目组不再静默借用全局 API 配置，必须先显式绑定。
- 图像、普通视频和 Omni 视频将租户写入生成与异步任务；图片/视频执行、重启恢复和 Omni 模型能力均依据持久化租户选择配置。
- 已认证请求把租户写入异步请求上下文，文本/视觉类 AI 调用和自动文本计费也会按当前项目组解析配置与价目；异步视频恢复仍以已持久化租户为准。
- AI 工具运行也持久化 `tenant_id`：新建、续写、服务重启后的再次执行均以原项目组的文本/视觉模型和价目解析，不会回退到全局配置。
- 授权、结算、释放账本与用量记录写入租户 ID；历史账本保持空租户 ID 和原读取语义。
- 运营配置页的无服务类型租户配置查询已覆盖回归测试，避免配置页 500。
