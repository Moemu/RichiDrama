# 项目组 API 与分组计费决策稿

## 已验证事实

新注册创作账号已完成真实本地 API 验证：可注册、可重新登录、自动加入“默认项目组”，并能读取 13 个模型。它不能进入运营后台是角色隔离；不能提交生成的直接原因是新建 `billing_accounts` 的余额为 `0`，预授权因此正确返回“余额不足”。这不是模型或租户配置被限制。

当前实现已经具备“平台管理员建配置、项目组绑定配置”的第一层隔离：`ai_service_configs` 保存受保护凭据，`tenant_ai_config_bindings` / `tenant_sd2_config_bindings` 让不同项目组只看被绑定的配置，任务保存 `tenant_id` 后在创建、轮询、恢复时按组解析。它的不足是凭据是全局配置库中的对象：所有凭据只能由平台管理员维护，组本身没有独立凭据生命周期、凭据版本、配额域或最后验证状态。

## 推荐目标

保留“一个用户一个钱包”的现有资金模型，新增“计费组”作为成本归集、预算和供应商凭据路由层。不要一开始把成员余额改为共享钱包：这会改变历史扣款语义且需要充值、退款、冻结迁移方案。

```text
请求人 user ─┬─ 属于 tenant（项目组）
             ├─ 可选属于 billing_group（部门/项目成本中心）
             └─ 使用 payer_account（当前默认自己的钱包）

billing_group ── 绑定 provider_credential（文本/图片/视频/SD2）
billing_group ── 绑定 price_book、预算和 quota_domain
生成任务/授权/用量 ── 固化 tenant_id、billing_group_id、payer_id、credential_id、价格快照
```

## 凭据规则

新增组级凭据版本，而不是让组直接修改全局 `ai_service_configs`：

```text
provider_credentials(
  id, tenant_id, billing_group_id, provider, service_type,
  encrypted_secret, base_url, models_json, quota_domain,
  status, version, effective_from, effective_to,
  last_verified_at, last_verify_error, created_by, created_at
)
```

- 平台管理员可跨组创建、禁用和审计；项目组管理员只能管理自己组内被授予的凭据（如果产品决定开放此权限）。
- 密钥只在后端解密使用；接口、日志、任务详情只返回掩码和版本号。
- 新调用解析顺序：明确选择的有效计费组凭据 → 租户默认凭据 → 默认项目组的旧全局配置兼容层 → 拒绝调用。
- 新任务把 `credential_id` 与 `credential_version` 固化到图片、视频、Omni、工具运行和异步任务；轮询、回调、重试均使用同一版本，管理员切换默认 Key 不影响已提交任务。
- SD2 的 Ark API Key 与素材审核 AK/SK 拆开保存并成对校验；它们不能互相替代。

## 计费规则

第一阶段维持个人钱包：`request_user_id = payer_user_id`，`billing_group_id` 仅用于价目、预算、成本报表与凭据选择。这样同组成员共享 API 与价目表，但每人的余额、冻结、退款、账本不混淆。

第二阶段（仅在确认需要“部门共享余额”后）新增统一付款主体：

```text
billing_payers(id, tenant_id, kind[user|group], subject_id, balance_micro, frozen_micro)
billing_group_members(group_id, user_id, role)
```

调用前明确 `payer_id`；预授权、结算、释放和历史快照全部写该付款主体。不得用成员标签或当前项目反推付款人。

## 新账号策略（需要产品决定）

1. **受控付费模式（当前）**：注册余额 0，管理员充值/划拨后才能生成。安全，但新用户会感到“受限”。
2. **试用模式（推荐）**：后台配置“注册赠送积分、有效期、每设备/手机号/邀请码限制”；注册时写一条可审计的 `trial_grant` 流水。默认额度应由运营配置决定，不能写死在代码。
3. **邀请码模式**：注册仍为 0；只有有效邀请码或管理员邀请会发放额度并指定项目组/计费组。

## 迁移与闭环

1. 先保留现有 `tenants`、成员、价目和全局配置绑定，默认项目组继续兼容旧数据。
2. 引入 `billing_groups` 和 `provider_credentials`，只对新组/显式迁移组启用；历史项目、素材、账本和任务保持现有读取路径。
3. 对每类生成任务固化凭据版本与计费组；用重启恢复测试证明不会改用新默认 Key。
4. 补齐按项目组、计费组、请求人、付款人、项目、模型的可复算报表和预算告警。
5. 所有密钥管理、价目/预算修改、成员调整与付款主体切换写审计日志；不自动迁移或改写历史余额。

- 已确认：新注册账号余额为 `0`，由管理员按需充值；不自动发放试用积分。
- 已确认：第一阶段保持个人钱包；成员调用各自扣款，项目组只共享 API/SD2、价目和成本归集。
