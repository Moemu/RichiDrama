# 项目工作流与分镜工作台修复计划

## 目标

恢复一条可用且一致的项目链路：自定义上传或 AI 生成资源 → 统一素材库 → 分镜工作台引用 → 镜头生成与合成。

## 问题与根因

1. **自定义角色图无法持续使用**：上传仅更新角色的 `image_url/local_path`，不会创建或更新对应的 `assets` 记录；分镜工作台只读取 `assets`。
2. **AI 资源无法进入分镜**：角色、场景、道具是独立实体，项目工作台没有将已生成的实体图纳入可拖拽的统一素材列表。
3. **样式冲突**：FilmCreate 与 FreeCreate 均有追加的全局深色/单色覆盖，项目内嵌工作台出现多套变量与布局规则叠加。
4. **镜头操作不完整**：项目模式隐藏了 FreeCreate 的新增、重命名、删除；左右栏高度与滚动约束也与嵌入模式冲突。
5. **提示词重复**：同一 `OmniAssetPromptEditor` 同时渲染于中央脚本区和素材栏，造成两个编辑器竞争同一个 v-model。

## 实施步骤

### 1. 资源持久化与统一素材映射

- 为角色上传、AI 角色生成、场景生成、道具生成后的图片建立或复用 `assets` 记录。
- 以资源类型、实体 ID 和本地路径写入来源元数据；重复操作复用已有素材，避免重复创建。
- 项目分镜工作台加载媒体素材后，再合并当前项目的角色、场景、道具图片；确保每一项均有有效 `asset_id`，可以保存到 `storyboards.omni_asset_ids`。
- 上传完成后刷新统一资源中心和当前工作台素材池。

### 2. 项目模式镜头 CRUD 与排序

- 在项目模式启用“当前镜头后新增”“删除镜头”“重命名”。
- 新增使用项目分镜 API，删除使用项目分镜 API；成功后重新加载当前集并选择合理的镜头。
- 拖拽排序采用稳定的插入目标逻辑，调用 `/storyboards/reorder` 后以服务端返回顺序刷新本地列表。
- 左侧素材栏与右侧镜头栏采用独立纵向滚动；窄屏退化为顺序区域，不截断内容。

### 3. 分镜工作台提示词与引用

- 项目模式只保留中央的一个提示词编辑器，移除素材栏内重复编辑器。
- 素材卡片可拖入中央编辑器，自动选中素材并写入规范 `@图片N` 引用。
- 保存时同时写入提示词、素材顺序、用途、首尾帧和生成参数；重新打开时可完整恢复。

### 4. 全局 UI 收口

- 将项目嵌入工作台限定在 `project-storyboard-page` 作用域，采用浅色中性面板、单一间距/边框/按钮语义。
- 清除项目模式下残留的深色覆盖和相互矛盾的 `!important` 规则。
- 统一 FilmCreate 的工作流卡片、资源中心、分镜工作台和合成页的浅色变量；不影响独立 FreeCreate 页面。

## 验收标准

1. 新建角色上传图片后，刷新页面仍显示，且可在分镜素材栏拖入提示词。
2. AI 生成的角色、场景、道具图均会出现在分镜素材栏，并可保存后再次打开恢复。
3. 可新增、删除、重命名、拖拽排序镜头；刷新后顺序和内容一致。
4. 每个分镜只显示一个可编辑提示词框，素材拖入后只更新该编辑器。
5. 资源栏和镜头栏在长列表下均可滚动；桌面和窄屏无重叠、截断或颜色冲突。
6. `npm run build` 与前端测试通过。
