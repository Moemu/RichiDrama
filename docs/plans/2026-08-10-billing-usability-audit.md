# 计费流程审查与优化记录

## 本次决定

取消“按用户分配模型使用权限”。只要模型已由管理员配置并具有当前生效的已发布价目，所有已登录用户都可以在余额充足时使用。`model_permissions` 历史表保留，不再参与运行时判断，也不再提供管理接口或后台入口。

这与内部计费的“预授权”不同：预授权是服务端在调用供应商前冻结额度的账务保护，必须保留。

## 审查结论与修复

| 事项 | 原风险 | 处理 |
| --- | --- | --- |
| 用户模型授权 | 新注册账号默认没有授权，无法操作，管理员维护成本高 | 移除逐用户授权与后台入口；模型列表展示所有已配置模型。 |
| 预授权生命周期 API | 客户端可直接请求结算或释放冻结，可能干预真实账务 | 移除公开的创建、结算、释放路由；仅由生成服务调用内部账务服务。 |
| 实际用量超出估算 | 结算金额可能高于冻结额，导致冻结余额异常或结算失败后残留冻结 | 结算金额封顶为已冻结金额，超出部分记录为 `overage_micro`，不会向用户追扣。 |
| 零价条目 | 未勾选免费也可发布零价，容易误配置 | 已发布价目要求至少一个条目，零价必须显式标记免费。 |
| 用户理解 | 用户难以区分余额、冻结与可用额度 | 账户中心保留“可用/冻结/累计消费”三项，并将模型区更名为“平台可用模型”。 |

## 当前可操作流程

1. 管理员配置并发布价目表；未定价模型在供应商请求前被拒绝。
2. 用户发起生成；服务端报价并冻结预计最高金额，余额不足时直接提示。
3. 成功后服务端按快照结算；失败、取消时释放冻结。
4. 当供应商回报用量超过冻结估算时，本次只收取冻结金额，避免用户在未确认前被额外扣款；运营方可通过用量与流水审计该差额后调整定价。

## 后续建议

- 为管理后台的价目项编辑提供表单，而不是 JSON 输入，降低配置错误概率。
- 增加超时任务的后台巡检：超过阈值且未结算的预授权自动释放并记录审计。
- 接入供应商真实用量/请求 ID 后，对每类模型设置保守估算上限并监控 `overage_micro`。
