# SD2.5 与创作闭环改进方案

日期：2026-08-12
范围：素材、分镜、模型/计费、持久化与端到端验收。

## 已确认的边界

- 线上图片生成继续使用 GeekNow；不把本地 `image` / `storyboard_image` 的 Volcengine provider 改为 GeekNow，也不把 GeekNow 凭据同步到本地。
- 本地只同步线上 Volcengine 的 API Key 与分组等必要参数，且仅在服务器现有安全配置允许时同步，不能把密钥写入仓库或日志。
- OSS 采用“本地热副本 + 异步镜像 OSS”的双层持久化：本地先完成可用性保证，OSS 上传并校验成功后标记已镜像；供应商的短期签名 URL 不能作为完成结果。本地副本按保留期回收，不能在生成完成或首次镜像成功时立即删除。
- 用户可见的 AI 调用仅能经过项目 `/api/v1/...` HTTP API、鉴权和计费链路；验收不直接调用供应商 SDK/API。

## 现状审计

1. `assets` 已有 `drama_id`，后端按 `drama_id` 查询时能隔离；但项目分镜工作台默认前端范围是“全部素材”，请求本身也没有把项目作为必填范围，因此素材过多、误选跨项目素材的风险仍存在。
2. 分镜工作台目前将播放器、参数、素材池放在并列区域。提示词和参数均为 T0 创作输入：二者必须并列、常驻、同等易读易操作；视频预览和分镜列表是紧凑的次级工作区，既不能抢占 T0 面积，也不能缩小到按钮不可点击。
3. `@` 选择器当前只显示图标、名称和“已选”状态；需要显示真实可访问的缩略图，且须支持本地持久化 URL。
4. 时长现在有快捷按钮和任意数值输入；模型下拉保留“自动匹配”。目标是 4–15 秒逐秒下拉框，且模型必须显式选择，禁止隐式自动匹配。
5. 现有 SD2 识别、认证、后台轮询、资产注入与真实 usage 结算均已存在。SD2.5 已确认正式 SKU：`doubao-seedance-2-5-260628`；支持图像/视频/音频参考、编辑、延长和首尾帧，时长 4–30 秒、480P/720P、24fps、单请求最多 50 个参考素材（30 图、10 视频、10 音频）。正式计费为含视频输入 42 元/百万 tokens、不含视频输入 70 元/百万 tokens；必须以供应商实际 usage 结算、多退少补。
6. 线上部署分支已存在 `mediaStorageService`：视频有 `archive_status`、失败重试和本地→OSS 流程；上传素材会镜像 OSS。但图片生成没有同等的归档状态/重试记录，目录扫描器会在 OSS 上传成功后删除超过 5 分钟的本地文件，和“本地热副本”目标冲突。
7. `docker-compose.yml` 仅会默认读取 `.env`。线上已有 `minidrama.oss.env` 而未被加载，当前运行容器实际仍为 `storage.type=local`；部署前应建立 `.env` 符号链接并重启容器。线上 OSS 服务代码当前未同步到本地仓库且显示为未跟踪文件，必须先纳入仓库再继续改造，避免部署覆盖。

## 实施设计

### 素材范围与引用

- 后端资产列表增加明确的 `scope=project|global|available` 语义，项目范围严格 `drama_id`，全局范围严格当前用户全局素材；保留仅供兼容的 `available`，但项目工作台不默认使用它。
- 前端项目模式默认“本项目素材”，加载时携带 `drama_id` 并按范围重新获取而非先加载用户所有素材再过滤。`@` 选择器只接收当前范围素材，避免跨项目误引用。
- 上传、导入、镜头保存、历史读取和权限校验均带项目 ID；项目无权限时返回 404，不泄漏资源存在性。

### 分镜交互和视觉层级

- 提示词编辑器（含引用标签、素材缩略图）与生成参数（模型、比例、时长、分辨率、音频）均为 T0：在同一首屏、无需展开、具有同等视觉权重与键盘/鼠标可达性。生成按钮紧邻这两个 T0 输入区。
- 成片视频预览、历史版本和分镜列表均为次级工作区：采用紧凑的固定/最小可用尺寸，保留播放、切换、排序、重命名、删除等按钮的点击热区，且不得挤占 T0 编辑区。
- `@` 菜单和已引用标签都显示 40–64px 的真实缩略图，使用资产的 `url`（本地优先）并在失败时回退图标。

### 模型、时长与计费

- 移除 UI 中“自动匹配”可选项；若历史记录含 `auto`，显示为“需要重新选择”，提交前阻止。
- 通用视频界面使用 4–15 秒整数下拉框；SD2.5 专用能力映射扩展至 4–30 秒，按模型能力接口渲染合法秒数，后端在创建/更新镜头和视频任务处同步校验。
- 扩展 Seedance 2 家族识别至 `doubao-seedance-2-5-260628`，保留既有 SD2 认证资产注入路径，并增加 SD2.5 的图/视频/音频参考、编辑和延长能力声明。只有存在该模型已发布 `billing_price_book_items` 时才能创建真实任务；计费项按“含视频输入 42 / 不含视频输入 70 元每百万 tokens”建立，使用供应商真实 usage 结算；无价目时返回明确配置错误。
- GeekNow 图像适配采用其 OpenAI Images 兼容提交/异步查询结构；任务必须先记录 `processing`，后台轮询完成后下载并归档，计费从项目账本预授权到结算/释放全程可追溯。

### 存储与部署

- 先将线上 `mediaStorageService`、迁移脚本、视频归档字段及测试以可审查提交同步回仓库，再实施功能调整；不得以本地缺失版本覆盖线上已存在的持久化逻辑。
- 图片、视频、上传素材及缩略图统一“本地先落盘 → 数据库 `local_ready` → 后台上传并校验 OSS → 数据库 `oss_synced`”路径。完成结果始终以稳定的 `local_path` 为资源标识，不保存供应商签名 URL。
- 以统一 `media_archives` 表（或在全部媒体实体一致扩展字段）记录 `local_path`、`oss_key`、状态、尝试次数、失败原因、校验时间、保留到期时间。上传成功后必须通过 HEAD/ETag 或 hash 校验才标记同步完成。
- 删除目录扫描式“成功即删”归档策略。回收任务只能选择 `oss_synced`、超过保留期、未被生成/导出任务占用的文件；视频默认保留 7–14 天，图片及缩略图默认保留 30 天。同步失败、校验失败或状态未知时绝不删除本地文件。
- OSS 使用私有桶；`/static` 在项目鉴权后签发短效访问 URL 或代理对象内容，不把可长期猜测的公开 CDN URL 作为授权边界。
- 第一阶段启用 OSS 时只进行“上传 + 校验 + 记录”，保持 `auto_archive_enabled=false`，不删除历史/新生成本地文件；通过完整验收后才启用按保留期的回收任务。
- 在服务器 `/data/apps/LocalMiniDrama` 建立 `ln -sf minidrama.oss.env .env` 并安全重启 compose。重启前检查环境文件与非空关键项，重启后检查容器有效配置、健康端点、OSS 只上传镜像与回退读取；不输出任何密钥。

## 执行顺序与回滚

1. 先补测试，实施范围/交互/模型校验与存储归档。
2. 运行后端测试、前端测试和 production build。
3. 仅通过项目 HTTP API 执行真实验证；真实调用之前确认测试账户余额、对应模型的有效价目和计费授权。
4. 先将线上 OSS 实现同步、提交并通过测试；随后建立 `.env` 符号链接，以“仅镜像、不删除”的模式 compose 重启并健康检查。若 OSS 配置不完整，撤销符号链接并恢复原容器配置，不进行生成任务。

## 外部资料核验

- GeekNow 文档说明图像生成可使用 `/v1/images/generations` 或异步接口，并且异步任务必须查询终态；其 Seedream 系列支持 OpenAI Images 兼容请求。https://docs.geeknow.top/api-reference/images/overview
- SD2.5 的模型 ID、能力和价目以用户提供的当前 Volcengine ModelArk 控制台信息为准：`doubao-seedance-2-5-260628`，含视频输入 42 元/百万 tokens、不含视频输入 70 元/百万 tokens。

## 已实施：OSS 可读兜底后的本地保留期清理

- 新生成的图片、视频和上传素材先保留本地热副本，并异步镜像到 OSS；镜像成功后记录 `oss_synced` 和 `local_delete_after`。
- 定时任务只查询已记录且已到保留期的 `oss_synced` 文件，绝不扫描目录后按文件年龄删除，因此未入库、未镜像或状态未知的本地文件不会被误删。
- 每次真正删除前，服务会使用签名 `HEAD` 请求回读该 OSS 对象；只有 HTTP 2xx 且对象有有效长度时才删除本地副本并标记 `local_pruned`。回读失败时，本地文件继续保留，记录失败原因，并将下一次检查延后一天。
- 默认保留期为：视频 14 天，图片、音频和其他媒体 30 天；可通过 `storage.oss.local_retention_days` 分别设置 `video`、`image`、`audio`、`default`（1–3650 天）。保留期清理仅在 `storage.type=oss` 且 `storage.oss.auto_archive_enabled=true` 时启用。
- OSS 私有桶仍由项目受保护的 `/static` 路由代理读取；本地副本被清理后，用户访问同一个本地媒体 URL 时由 OSS 回读兜底，不暴露供应商签名 URL。

## 本地真实验收记录（2026-08-12）

- 已用管理员项目 HTTP API 发起 `doubao-seedance-2-5-260628` 最低成本请求：纯文本、480P、4 秒。供应商任务创建成功并完成，视频生成记录为 `58`，稳定媒体地址为 `/static/library/videos/vg_58_194867e7.mp4`；服务重启前后可按 `local_path` 恢复，静态回读返回 HTTP 200、`video/mp4`、2,224,518 bytes。
- 计费闭环：先预授权 300,000 output tokens（2,100 点），供应商真实返回 `output_token=38,830`，最终结算 2,718,100 micro-points（271.81 点）；使用量日志与供应商任务 ID 均已持久化，剩余预授权自动释放。
- SD2 自动认证已有多个 `active` 资产并可被 `asset://` 注入。额外修复：对于图片损坏、认证服务拒绝等永久提交失败，认证状态会改为 `failed` 并保留可读原因，不再保持 `queued` 后无限轮询；用户重新上传或重新选择有效图片后可再次认证。
- 本次补充验收已将部署用 OSS 配置安全同步到本地被忽略的 `minidrama.oss.env`，本地服务实际解析为 `storage.type=oss`。通过项目 HTTP API 上传的测试图片已获得 `oss_synced` 记录与有效 OSS HEAD 校验；服务重启后仍可读取本地热副本。
- 将该测试资产模拟为到期后，回收任务先 HEAD 校验 OSS 再删除本地副本，状态转为 `local_pruned`；经鉴权的同一 `/static/...` 地址仍以 HTTP 200 从 OSS 回读完整内容。密钥文件、测试数据库和日志均不提交。
