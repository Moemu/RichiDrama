# 素材复用、覆盖与认证状态修复方案

## 现象与结论

当前系统存在两类记录：

1. `assets`：上传、生成和媒体库中的真实素材，分镜以 `asset_id` 引用它。
2. `characters`、`scenes`、`props`：项目资源；现有 `assetMappingService` 会把它们的图片再投影为 `source_type=project_resource` 的 `assets` 记录。

旧链路的复用依赖 `assets.id`：分镜保存该 ID，素材库再次加载同一 ID，因此名称、标签、认证状态和引用可以持续存在。

新链路把项目资源投影当作可随时重建的临时卡片，但它仍被分镜当作稳定 `asset_id` 使用，造成了生命周期冲突：

- 同步发现源资源无图时会软删除投影素材；旧分镜仍保存旧 ID，后续校验把引用移除。
- 同步每次都将源资源的 `seedance2_asset` 写到投影素材。若历史认证只保存在素材记录中、源资源为空，就会把“可用”认证覆盖成 `null`。
- 媒体库为了避免删除项目资源，隐藏了投影素材的编辑/删除按钮；当其源资源又已不存在时，用户没有可执行的修复入口。
- `metadata_json` 中的资源类型和 ID 被当作关系主键，且没有唯一约束；同一资源可能产生多个投影，列表选择最新记录后，状态看起来随机消失。

因此，认证状态消失和无法复用并非供应商认证失效，而是“真实素材”和“项目资源映射”混用同一张卡、但没有明确生命周期造成的。

## 目标与不变量

- 一个素材 ID 一旦被分镜引用，不能被同步流程删除或悄悄替换。
- SD2 认证属于具体文件内容；它必须随真实素材保存，不能被空的项目资源状态覆盖。
- 项目资源只保存“当前使用哪个素材”的关系；覆盖应产生新版本，历史分镜仍可回放。
- 删除必须区分“解除关联”和“从素材库移除”，并在存在分镜引用时阻止直接删除。
- 升级后能识别历史投影、修复认证状态，并向用户展示无法自动恢复的失联项。

## 数据模型

新增 `asset_resource_links`，避免继续把关系塞入 `metadata_json`：

| 字段 | 含义 |
| --- | --- |
| `id` | 主键 |
| `drama_id` | 项目范围 |
| `resource_type` | `character` / `scene` / `prop` |
| `resource_id` | 对应项目资源 ID |
| `asset_id` | 当前真实素材 ID |
| `role` | 目前为 `primary_image`，后续可扩展参考图 |
| `status` | `active` / `detached` / `missing_source` |
| `created_at`, `updated_at` | 审计时间 |

对 `(resource_type, resource_id, role)` 建立唯一索引。`assets` 保持素材的唯一事实来源：文件地址、标签、收藏、认证、版本谱系均只写入 `assets`。角色/场景/道具表保留旧图字段作为兼容读取来源，迁移完成后不再覆盖 `assets` 的状态。

## 迁移与修复策略

1. 建表并扫描所有 `source_type=project_resource` 的历史素材，把 `metadata_json.resource_type/resource_id` 转为链接记录；同一资源优先保留仍存在、被分镜引用、认证状态更完整的一条。
2. 对每个链接做一次双向认证合并：优先 `active`，其次有 `hub_asset_id` 且更新时间较新的状态；写回真实素材。绝不以空状态覆盖非空状态。
3. 资源表存在图片而没有链接时，创建或复用真实素材后建立链接；资源表无图时，将链接标记 `missing_source`，不删除素材和分镜引用。
4. 扫描 `storyboards.omni_asset_ids`、首尾帧和 `omni_video_job_assets`：找不到素材的记录生成“失联素材”清单，不静默移除。若有同内容/同资源链接候选，提供可审计的批量修复；没有候选则保留引用并显示“需处理”。
5. 为旧投影保留兼容查找：在过渡期 API 读取旧映射时解析为链接目标，避免旧页面或历史任务立即 404。

## 用户操作语义

### 复用

素材库始终列出真实素材；项目资源卡显示“当前素材”和“更换素材”。同一素材可同时被多个资源和多个分镜引用。

### 覆盖

“覆盖图片”改为“上传新版本”：创建新 `assets` 行，设置 `parent_asset_id` 为旧素材，并将项目资源的 `primary_image` 链接指向新版本。默认只影响以后选择该资源的分镜。

若用户选择“替换现有未完成分镜”，后端在一个事务中替换指定项目内未完成分镜的引用，并显示影响数量；已生成视频和历史任务不改写。

### 删除

- 默认操作为“解除资源关联”，素材继续留在媒体库以保障历史分镜。
- “从素材库删除”先返回引用计数与引用位置；存在分镜/任务引用时禁止删除，改为“归档”。
- 无来源的旧投影显示 `missing_source`，提供“重新绑定素材”“归档”“从指定分镜移除”三项明确操作。

### SD2 认证

只从真实素材读取和更新认证状态。新版本文件的指纹变化会进入“未认证/需认证”，旧版本仍保留原认证和历史可回放性。

## 实施顺序

1. 后端：迁移表、链接服务、历史数据修复 API、引用计数 API；移除 `syncDramaAssets` 中的删除和空状态覆盖行为。
2. 后端：分镜保存/生成链路改为根据链接解析当前素材，但不自动清理历史 ID。
3. 前端：媒体库和统一资源管理增加链接状态、失联素材队列、重绑/归档/新版本覆盖向导。
4. 测试：覆盖“历史认证只在素材上”“源资源删图”“一个素材被多个分镜引用”“覆盖后历史分镜不变”“失联项不被静默删除”。
5. 上线：先运行只读审计，输出待修复数量；确认后执行数据修复，再开启新写入路径。

## 验收标准

- 重新同步项目资源不会改变已认证素材的认证状态，也不会删除已被引用的 `assets.id`。
- 已引用素材在源资源丢图后仍可从媒体库查看、重绑或归档。
- 覆盖素材后可明确看到新旧版本和受影响分镜数量。
- 删除存在引用的素材不会产生 404；用户能看到引用位置并选择解除关联或归档。
