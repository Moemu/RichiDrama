# 统一资源浏览器与按镜头素材盒改造方案

## 目标

解决项目资源增加后，用户必须在角色、场景、道具三列长列表中反复滚动查找的问题；同时将“可复用项目资源”和“本镜临时素材”分开，避免素材库变成所有分镜的全局引用池。

## 已确认的产品语义

1. 角色、场景、道具是项目级统一资源，可跨分镜复用。
2. 图片、视频、音频可以按镜头上传；它们默认只属于当前镜头的素材盒。
3. 项目素材库是可复用来源，不是所有分镜的自动可选集合。
4. 已用于生成的任务和历史结果保留请求快照，不被素材库的后续整理破坏。

## 第一阶段（本次实现）

### 资源中心：三列长列表改为单一资源浏览器

- 将“角色 / 场景 / 道具 / 项目素材”改为同一组可切换的标签页；一次只浏览一种资源，不再在三个内部滚动区中找人。
- 增加名称、描述、别名的即时搜索；增加“全部 / 有图片 / 待补图”筛选。
- 卡片网格展示图片、名称、摘要和资源类型；批量选择与批量删除仍按当前资源类型工作。
- 工具栏按资源类型提供正确动作：从剧本提取、添加、上传图、生成缺图、批量删除、管理项目素材。
- 项目素材在资源浏览器中仅作为“可复用项目素材”管理入口；文案不再宣称会自动进入每个分镜。

### 删除体验：镜头隔离、项目归档与危险操作分离

- 在镜头素材盒点击 `×` 只会“移出当前镜头”，不会改动项目素材库，也不会影响其他镜头。
- 项目素材库的单条与批量删除调整为“归档”：归档素材不再给新镜头选择，但已有可编辑镜头、已提交任务、完成视频和历史记录继续保留原有引用与快照。
- 只有在素材详情中明确执行“从全部可编辑镜头解除并归档”时，系统才会批量移除各镜头的素材选择、首尾帧、素材用途及相应 `@` 引用；已提交任务和历史记录不变。

### 可用性与视觉约束

- 搜索框有可访问名称，状态筛选使用原生可聚焦按钮。
- 所有操作保持可见文本；选择状态同时用边框、勾选框和数量表达，不依赖颜色。
- 卡片区只在自身容器内纵向滚动；页面仍可到达下一步操作。
- 使用响应式网格，在 1280×720、1440×900、1920×1080 下不产生页面横向溢出。

## 分镜交互（本次已落地）

### 分镜素材盒

- 每个分镜读取并维护自己的已选素材清单，而不是直接把项目媒体库铺为活引用池。
- 分镜工作台的“当前镜头素材”只显示本镜已加入素材；新上传媒体固定上传到当前项目并自动加入本镜。
- “从项目素材库加入本镜”以独立可搜索面板提供项目/全局范围切换；点击卡片加入或移出本镜，中文类型词（如“音频”）也可检索。
- 角色、场景、道具仍在统一资源中项目级共享；媒体只有加入镜头后才出现在该镜头工作集。

### 删除语义

- 移出本镜素材：仅移除本镜已选状态；提示词的 `@` 引用由用户在编辑器中显式调整，避免光标输入时发生隐式清空。
- 从项目素材库归档：默认仅隐藏素材库来源；既有镜头、生成任务和历史记录保持不变。
- 从全部可编辑镜头解除并归档：显示危险确认后，才批量移除镜头引用及对应 `@` 引用。
- 删除统一角色、场景、道具：默认仅从资源中心归档，保留历史镜头快照；“同时从后续镜头解除引用”是明确确认的危险操作。

## 数据与兼容边界

- 保持既有删除 API 路径，默认语义升级为可重复执行的归档；新增显式 `force-detach` 路径作为危险操作，不改写历史任务快照。
- 新增 `assets.archived_at` 前向兼容字段；旧分镜保持现有读取路径，归档前已存在的引用仍可读取，且不改写历史生成任务。
- 不在本次 UI 验收中调用供应商 API 或产生计费。

## 验收清单

- 前端自动化测试、production build 均通过。
- 内置浏览器在 1280×720、1440×900、1920×1080 检查资源中心：标签切换、搜索、筛选、批量选择、纵向滚动、最后操作项和无横向溢出。
- 本地审查不执行真实删除确认，不修改本地业务数据；API 行为保持既有覆盖。
