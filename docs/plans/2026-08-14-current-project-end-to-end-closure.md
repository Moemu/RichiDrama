# 当前项目完整闭环说明与验收清单

> 版本：2026-08-14
> 适用范围：LocalMiniDrama 当前后端、前端、SQLite、本地媒体存储与火山 AI MediaKit 视频后处理接入。
> 积分口径：`1 元 = 100 积分`；账本内部 `1 积分 = 10,000 微积分`。
> 发布原则：全部改动前向兼容；不重算、不覆盖、不删除线上既有业务数据。

## 1. 闭环目标

用户从登录进入项目后，可以在隔离的素材域中组织角色、场景、道具和上传素材；分镜继承项目默认的视频规格，也可以按镜头覆盖；视频生成、可选超分、可选插帧依次完成；每一阶段的供应商调用、计费、文件落盘、恢复状态和审计记录均可追溯。

```mermaid
flowchart LR
  A[登录 / JWT 与 HttpOnly Cookie] --> B[项目与分镜]
  B --> C[全局素材库 / 当前项目素材库]
  C --> D[SD2 认证与素材引用校验]
  D --> E[视频生成：processing]
  E --> F[本地持久化原始输出]
  F --> G{开启 AI 超分?}
  G -- 是 --> H[MediaKit 超分]
  G -- 否 --> I{开启智能插帧?}
  H --> I
  I -- 是 --> J[MediaKit 插帧]
  I -- 否 --> K[最终本地视频]
  J --> K
  K --> L[结算 / 用量 / 审计 / 素材展示]
  L --> M[重启恢复与可选 OSS 归档]
```

## 2. 认证、权限与数据隔离

### 2.1 登录态

- 用户通过 `POST /api/v1/auth/login` 登录，服务端签发 JWT，同时设置 `lmd_session` HttpOnly Cookie。
- 所有业务 API 在 `requireAuth` 后执行，后端以 `req.auth` 作为付款人和资源所有权主体，客户端不能传入其他用户作为计费主体。
- `POST /api/v1/auth/session-cookie` 用于已验证 Bearer 会话刷新媒体访问 Cookie；用户名、角色和会话更新会同步处理 JWT、Cookie 与前端当前用户状态。

### 2.2 素材域

| 域 | 归属 | 可见范围 | 关键约束 |
|---|---|---|---|
| 全局/个人素材库 | 当前用户 | 仅当前用户 | 不能被其他用户按 ID、校验和或列表接口读取 |
| 项目素材库 | 项目及项目所有者 | 项目授权范围 | 项目所有者保有 CRUD；资源映射保留来源与版本关系 |
| 分镜引用 | 具体分镜 | 当前项目 | 仅保存已授权素材引用，删除/解绑用 tombstone 阻止旧同步任务复活 |

- 同一文件校验和只在同一素材域内去重，绝不跨用户或跨项目复用。
- 资源解绑不是物理删除：显式删除记录 tombstone，后续素材同步不得重新关联；恢复必须是明确的恢复操作。
- 供应商 URL 只可作为下载输入，完成态素材、分镜和视频列表只使用本地相对路径或经存储服务管理的持久化路径。

## 3. SD2 认证闭环

1. 用户声明涉及真实人物的角色/素材后，前端调用项目认证接口建立认证任务。
2. 后端先验证素材所有权和 SD2 资产映射，再持久化 `processing` 状态、供应商任务标识和审计信息。
3. 后台轮询认证结果；成功后将认证状态写回规范资源及其映射，失败则持久化错误，永久错误不无限重试。
4. Seedance/SD2 视频提交前检查引用素材：未认证的真实人物素材拒绝提交；认证仍在处理中返回等待状态；已认证才允许进入供应商调用。
5. 服务重启后扫描未终态认证记录并继续轮询，不需要前端保持页面开启。

## 4. 分镜设置与视频参数继承

### 4.1 默认与覆盖

- 项目级生成设置是分镜的默认来源：默认输出 `720p`，默认开启 AI 超分到 `1080p`，默认关闭插帧（`target_fps=null`）。
- 分镜可保存 `video_resolution`、`video_aspect_ratio`、`video_upscale_resolution`、`video_target_fps`，覆盖项目默认值；缺失字段继续继承。
- Omni 分镜、普通视频生成和导入后的分镜使用同一后处理策略归一化逻辑，避免不同入口得出不同的超分/插帧设置。
- 当输出分辨率已等于超分目标时，后端自动清空超分，避免无意义的供应商调用和扣费。

### 4.2 规格合同

- 画幅由分镜参数统一规范化，不允许后处理把 9:16、16:9、1:1 等比例静默变形。
- `target_fps` 未设置即明确为“不开启插帧”，不是创建后再释放的伪关闭。
- 分镜详情、镜头配置、生成请求快照和视频记录共同展示最终使用的规格与后处理链路。

## 5. 视频生成、超分、插帧与本地持久化

### 5.1 请求与预授权

1. 前端可先调用 `POST /api/v1/videos/postprocess-quote` 预览原视频、超分、插帧各阶段预估积分。
2. 提交视频生成时，后端校验登录态、项目/分镜/素材所有权、模型权限、SD2 条件和价格覆盖情况。
3. 原视频生成先创建计费预授权和 `video_generations` 记录，状态写为 `processing`，随后才调用供应商。
4. 若启用超分或插帧，分别创建独立的后处理预授权及 `video_upscale_jobs`、`video_interpolation_jobs`；其幂等键绑定 `video_generation_id`，重复请求不会重复扣费或重复提交。

### 5.2 执行顺序

1. 供应商原视频完成后，下载并落盘为 `source_local_path`，同时记录供应商任务 ID、请求 ID、真实 usage 和生成结算快照。
2. 若启用超分：以本地原片为输入，调用火山生成式增强；完成文件先落盘为 `upscale_local_path`，再以真实时长、分辨率、帧率结算。
3. 若启用插帧：优先以超分后的本地视频为输入；若未超分则用原片。完成文件落盘为插帧输出，并更新最终 `local_path`、尺寸、fps、时长和完成时间。
4. 视频列表、分镜画布、Omni 历史记录、合成/下载入口均读取最终持久化路径；不会以供应商签名 URL 作为完成结果。

### 5.3 原片保留策略

- 未启用超分：原片就是最终素材，保留。
- 启用超分：超分完成且最终文件已持久化后，新的任务可按 `intermediate_cleanup_enabled` 删除不再需要的原片；若还启用插帧，会等插帧最终完成后再执行清理。
- 清理只针对新建且显式开启该策略的任务，历史视频记录默认关闭；不会影响线上历史文件、历史视频字段或已完成素材。
- 文件删除后同步清空对应中间路径字段，避免界面返回失效路径；最终 `local_path` 始终存在于完成态视频。

### 5.4 异步状态与恢复

| 阶段 | 主要状态 |
|---|---|
| 原视频 | `processing`、`persisting`、`completed`、`failed` |
| 超分 | `awaiting_source`、`pending`、`processing`、`completed`、`failed`、`reconciliation_required` |
| 插帧 | `awaiting_source`、`pending`、`processing`、`completed`、`skipped`、`failed`、`reconciliation_required` |

- HTTP handler 只持久化任务和启动后台流程，不在请求内长期轮询供应商。
- 启动时恢复未终态视频、超分、插帧和 SD2 认证；已完成任务按记录读取，不会重新提交供应商任务或重复结算。
- 如果上游视频失败，尚未调用的超分/插帧预授权会被作废释放。

## 6. 计费、价目与对账闭环

### 6.1 统一账务顺序

每一次实际供应商能力调用严格遵循：

`鉴权 → 模型权限 → 价目匹配 → 预授权冻结 → 供应商调用 → 本地持久化 → 按真实 usage 结算 / 待对账 / 释放`

- 真实供应商调用只能由后端 HTTP 业务路由引发；脚本、浏览器、测试工具不能绕过业务 API 直接调用供应商。
- `billing_authorizations` 保留冻结金额、幂等键、价格快照和关联业务 ID；`billing_transactions` 保存变动流水；`billing_usage_logs` 保存供应商 usage 与结算来源；`billing_reconciliation` 保存真实用量缺失或超出预授权时的待人工处理记录。
- 价格按整数微积分计算，避免浮点误差；用户界面按积分展示，金额精度最高为 0.0001 积分。

### 6.2 AI MediaKit 后处理价目

火山 AI MediaKit 按输出分钟定价、按毫秒精确计算。项目正式价目以分辨率与 fps 档位匹配，不以一个低价兜底值替代真实档位。

| 能力 | 条件价（积分/输出分钟） |
|---|---|
| 生成式增强/超分 | 720p：250/500/1000；1080p：500/1000/2000；2K：1000/2000/4000 |
| 视频插帧 | 720p：60/120/240；1080p：120/240/480；2K：240/480/960；4K：480/960/1920 |

每组三个数依次对应 ≤30 / ≤60 / ≤120fps。管理端显示条件价区间；无规格上下文时的安全兜底分别为插帧 `120 积分/60,000ms`、超分 `1000 积分/60,000ms`。历史账本、使用日志、授权快照和用户自定义价目表不因价目修正而重算。

## 7. 存储、归档与下载

- 完成的图片与视频先落本地媒体目录，数据库持久化相对路径和必要的媒体探测信息。
- 可选 OSS 归档使用 `media_archive_records` 与视频归档状态保存上传、校验和、重试和本地删除延迟；只有远端对象经校验后，才允许按保留策略清理本地副本。
- 归档失败保持本地副本并记录失败原因，不会用不可恢复的供应商 URL 兜底。
- 用户可通过素材库、分镜、视频任务和成片入口恢复访问已完成文件；列表刷新和服务重启后仍可读取。

## 8. 线上兼容与数据安全边界

- 数据库使用前向 SQL 迁移与 `ensureColumns()`，新增列均允许历史数据为空并有默认/兼容读取逻辑。
- 历史分镜缺少后处理字段时继续按项目默认设置读取；历史视频缺少中间文件字段时仍按原 `local_path` 展示。
- 所有业务时间以 UTC ISO 格式存储、传输；界面统一显式使用 `Asia/Shanghai` 格式化。
- 不修改现有用户、余额、历史结算、历史供应商记录、历史素材文件和已完成视频；任何清理仅面向新任务且需显式开关。
- 本地调试可通过 `CFG_IMAGE_PROXY__USE_FOR_VIDEO=false` 关闭视频图片中转，线上不设置该变量，继续读取既有 `config.yaml` 行为。

## 9. 验收步骤

1. 启动后端与前端，使用普通用户登录；刷新页面后确认会话、项目、素材和视频仍可读取。
2. 创建项目，分别上传个人素材、关联项目素材、解除关联并刷新；确认两域不串数据，解除的资源不被同步任务自动恢复。
3. 创建/选择需要认证的真实人物素材，确认 SD2 任务从 processing 进入终态；未完成认证的素材不可提交到要求认证的视频模型。
4. 在项目设置确认默认 `720p → AI 超分 1080p → 不插帧`；修改一个分镜为覆盖配置并检查其他分镜不受影响。
5. 调用 `POST /api/v1/videos/postprocess-quote`：验证 1080p ≤60fps 插帧为 240 积分/分钟、1080p ≤30fps 超分为 500 积分/分钟。
6. 通过视频业务 API 发起任务，检查依次有生成、超分、插帧（仅显式设置 fps 时）各自的授权、任务 ID、usage、结算和本地文件。
7. 任务处理中重启后端，确认任务恢复；完成后刷新分镜、视频列表和素材库，确认只显示最终本地视频。
8. 检查账户流水、用量日志和待对账列表：真实 usage 可结算，缺失/超额 usage 进入待对账，不发生静默透支。
