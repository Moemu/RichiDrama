# 分镜参数、素材交互、媒体预览与积分体系闭环改进方案

> 日期：2026-08-13
> 状态：已实施并完成自动化与内置浏览器验收
> 范围：分镜工作台、自由创作、素材引用、视频预览、管理员积分
> 原则：不直连供应商，不改变现有 AI 鉴权与计费入口；所有真实生成仍经 `/api/v1/...` 完成。

## 2026-08-13 三次纠正：视频状态必须真实表达

本节为最新口径，并覆盖下文所有“无视频也显示分镜图/通用图片占位”的旧描述：

- 尚未生成完成视频的镜头，列表与中央预览显示统一的紫色播放卡，只表达“这里还没有视频”，不得用分镜图、参考素材或通用风景图冒充视频首帧。
- 已生成完成且存在本地持久化视频的镜头，列表直接挂载该真实视频（优先使用其持久化海报作为 `poster`，没有海报则由视频元数据呈现首帧）；点击镜头后中央唯一播放器立即切换真实本地视频并自动播放。
- 首屏加载必须一次性解析全部可见镜头的完成视频。除当前 `storyboard_id` 外，同时携带 `episode_id + storyboard_number` 查询，兼容视频仍绑定在历史/已替换分镜行上的旧数据；不能等用户点击镜头后才通过历史接口补出视频画面。
- 列表中的视频统一 `muted + playsinline + preload=metadata`，只加载元数据/首帧，不自动播放多个缩略视频，以平衡滚动性能和真实观感。
- 判断依据是已完成视频的本地 `video_url/local_path`，不是分镜是否存在图片；供应商签名 URL 仍不得作为完成态兜底。
- 管理员积分调整的“情况说明”为选填；为空时由后端写入可审计的默认原因。
- `@` 素材浮层面向大量素材采用“全量名称匹配、最多渲染前 30 项、缩略图懒加载、浮层内部滚动”的固定成本策略；超过 30 项时明确提示总数并引导用户继续在 `@` 后输入名称筛选，素材规模增长不会扩大浮层或一次挂载全部缩略图。

## 2026-08-13 二次纠正：首镜母版、真实图片占位、虚影素材层

本节覆盖下文中与这三项冲突的旧描述，并作为本轮实施依据。

### 1. 镜头列表必须始终是“图片墙”

镜头导航不再用带播放按钮的紫色视频卡作为空态。封面按以下顺序解析：

1. 已完成视频的本地 `poster_local_path`；
2. 分镜已生成的 `composed_image`、`image_url` 或图片 `local_path`；
3. 首帧、尾帧或当前镜头引用的第一张图片素材；
4. 本地无文字、无播放按钮的电影画面占位图。

占位图本身必须具备天空、远景、地面和光影层次，看起来是一张尚未替换的分镜画面，而不是播放器、图标或文字空态。镜头列表永远只挂载 `<img>`，不挂载 `<video>`。

### 2. 参数语义改为“首镜母版”

用户所说的同步不是“第一次任意镜头建立本集默认”，而是明确以镜头列表中的第一个镜头作为参数母版：

- 第一个镜头显示“首镜母版”；修改它时，更新本集参数母版，并同步所有仍处于继承状态的后续镜头。
- 后续已有镜头默认显示“跟随首镜”；首镜变化时自动更新。
- 后续新建、插入或 AI 新生成的镜头，初始化时直接使用首镜母版参数。
- 用户在后续镜头改参数后，该镜头转为“当前镜头覆盖”，以后不再被首镜变化覆盖。
- 用户点击“恢复跟随首镜”后删除覆盖值，立即采用首镜当前参数。
- 首镜不能进入覆盖状态；即使数据库中存在旧覆盖值，读取时也要归一为母版。

后端继续保留 `episodes.generation_defaults_json` 作为持久化母版，但其业务名称和写入来源统一解释为“首镜母版”，不再向用户展示抽象的“本集默认”。有效值仍采用 `首镜母版 + 当前镜头覆盖`，兼容现有物化列和历史数据。

### 3. `@` 素材框改为“虚影素材层”

素材框必须是覆盖式浮层，不能挤占提示词区域，也不能永久遮住视频区域：

- 使用 `Teleport` 和 fixed 定位，完全脱离页面布局。
- 浮层采用约 68%～78% 不透明度、背景模糊和轻边框；下方提示词/视频仍能被感知，形成“虚影”效果。
- 最大高度取视口和编辑器可用空间的较小值，默认不超过 260px；素材多时仅浮层内部滚动。
- 宽度跟随提示词编辑器但设上限，优先向上展开；空间不足时向下展开，不改变任何栏位尺寸。
- 保留光标处的半透明 `@素材` 插入预览，选中或按 Escape 后浮层立即消失。
- 大素材集采用紧凑横向卡片，缩略图惰性加载；不恢复大面积实体素材面板。

### 二次纠正验收

1. 当前截图所示右侧五个镜头，即使没有生成图，也全部显示无文字的电影画面图片，不再出现紫色播放卡。
2. 修改首镜时，所有“跟随首镜”的后续镜头同步；修改第二镜只影响第二镜并标记覆盖；新增镜头直接取得首镜参数。
3. `@` 浮层覆盖在内容上方且能透出下方画面，关闭后不留下空间；素材数量增加只产生浮层内部滚动。

### 4. 计费说明与视频占位补充

- 管理员发放、扣减和余额校正的“情况说明”改为选填；为空时后端写入明确的系统默认原因，流水、操作类型、前后余额和操作者仍完整可审计。
- 镜头导航首先使用已完成视频持久化的首帧海报。尚无视频或首帧提取失败时，使用本地无文字的视频画面占位图；占位图只表达“这里将是一帧视频画面”，不出现播放按钮、文字或加载 `<video>`。
- 分镜图片和引用素材只在尚未生成视频时作为更贴近镜头内容的预览；一旦存在本地视频海报，必须覆盖这些预览。

## 一、结论摘要

本轮建议采用以下统一方案：

1. 分镜参数改为“本集默认参数 + 单镜覆写”。第一次在尚未建立默认值的分镜中调整参数时，自动建立本集默认值并同步所有未覆写分镜；之后在某个分镜中修改，默认只影响当前镜头。用户仍可显式选择“更新本集默认并同步未覆写镜头”。
2. `@` 素材选择器使用 `Teleport` 浮动到提示词框上方，宽度跟随编辑器，使用 2～4 列图片卡；编辑区保留插入光标、半透明 `@素材名` 幽灵预览和弹层指向锚点，用户无需猜测插入位置。
3. 列表与历史版本全部显示图片海报，不再使用文字占位。完成视频持久化首帧海报；生成中使用分镜首帧/主图；仍无图片时使用本地无文字电影画幅占位图。页面只保留一个活动视频播放器，点击镜头立即切源并播放。
4. 积分操作默认使用“追加积分/扣减积分”，直接影响余额并产生独立流水；“设置余额”改名为“余额校正”，作为低频管理操作单独入口。账号同时展示累计发放、累计消费、累计退款/冲正、当前余额和冻结金额，累计消费只由真实结算增加，不能通过设置余额推算。
5. 拖动定位改为“排版缓存 + `requestAnimationFrame` 合帧 + 行级索引 + 幽灵引用预览”。禁止在每个 `dragover` 中重建 DOM 并逐字符测量，目标是插入光标在一帧内跟随鼠标。
6. 提示词采用“服务端自动保存 + 本地草稿日志”双保险。输入后自动持久化，刷新时先读取服务端，再仅在本地草稿更新时恢复；成功保存后清理草稿，避免刷新、崩溃或网络瞬断造成提示词丢失。

这套方案的核心是保存“继承/覆写、充值/校正、海报/播放器、真实落点/视觉反馈”的业务语义，而不是只复制最终数值或只隐藏卡顿。

## 二、现状与根因

### 2.1 分镜参数

当前 `FilmCreate.vue` 同时存在项目级 `GenerationSettings`、“应用到全部分镜”按钮和每镜 `GenerationSettings`。每镜修改会在 350ms 后直接写入：

- `duration`
- `text_model`
- `video_model`
- `video_resolution`
- `video_aspect_ratio`

加载时又把项目值回填进每条分镜的前端对象，因此页面只能看到“最终值”，无法判断某字段是继承本集默认还是当前镜头主动覆写。继续复制值到所有分镜会导致后续无法安全地只同步未自定义镜头。

### 2.2 `@` 素材框与拖入定位

`OmniAssetPromptEditor.vue` 的素材框处于普通文档流，最高 200px，缩略图为 96×96，实际常只能看到一项；素材框出现后还会挤压编辑区。`UniversalSegmentOmniAtEditor.vue` 已使用 `Teleport`，但宽度固定约 280px，仍不适合素材浏览。

普通 textarea 的拖动实现会在每一次 `dragover` 中：

1. 新建镜像 DOM；
2. 复制全部排版样式；
3. 对提示词逐字符创建 Range 并测量；
4. 删除镜像 DOM。

这是光标落后鼠标的直接原因，复杂文本下开销随字符数线性增加，并触发布局计算。

### 2.3 视频资源预览

当前优化已经把非活动分镜和历史视频改成轻量占位，减少了 `<video>` 数量，但出现了新的体验问题：无海报时显示“点击加载本镜视频”等文字块，破坏镜头墙的整体画面感；点击镜头只挂载播放器，不会立即播放，仍需第二次操作。

素材表已经支持 `thumbnail_local_path`，但分镜视频记录没有统一、可靠的持久化海报字段。直接恢复多个 `<video>` 缩略播放器会重新引入 Range 请求、解码上下文和滚动卡顿，不能作为解决办法。

### 2.4 积分分配

后端同时具备两种能力：

- `adjustBalance`：按差额追加或扣减，正数累计到 `total_recharged_micro`；
- `setBalance`：把余额直接校正为目标值，流水记录差额与 `set_balance` 快照。

管理员页面却只提供“设置积分余额”，把低频校正暴露成主流程。账号表已有 `total_recharged_micro`、`total_consumed_micro`，真实调用结算时会累加消费，但用户列表未展示这些累计值。因此“无法算总消耗”并非缺少消费账本，而是主交互选错、统计字段未暴露。

## 三、详细设计

## 3.1 分镜参数：本集默认 + 当前镜头覆写

### 交互规则

分镜参数卡显示状态徽标：

- `继承本集`：使用本集默认参数；本集默认变化时自动更新。
- `当前镜头自定义`：只保存本镜覆写字段；本集默认变化时不覆盖这些字段。

首次配置规则：

1. 当前集尚无 `generation_defaults`，且所有分镜无覆写时；
2. 用户在任一分镜修改参数；
3. 系统将该组参数设为本集默认并同步到所有分镜的有效展示；
4. 显示轻提示“已作为本集默认同步到 N 个镜头”，提供“撤销”。

后续修改规则：

- 在分镜参数卡直接修改：自动切换为“当前镜头自定义”，仅影响当前镜头。
- 点击“恢复本集默认”：删除该镜头覆写，立即重新继承。
- 在顶部“本集默认参数”修改：只影响仍处于继承状态的镜头。
- 显式选择“同步到全部镜头”：先预览影响数量；默认不覆盖自定义镜头，可勾选“同时覆盖 N 个自定义镜头”。

### 数据模型

新增：

```sql
ALTER TABLE episodes ADD COLUMN generation_defaults_json TEXT;
ALTER TABLE storyboards ADD COLUMN generation_overrides_json TEXT;
```

JSON 字段固定白名单：

```json
{
  "text_model": "auto",
  "video_model": "auto",
  "duration": 15,
  "resolution": "720p",
  "aspect_ratio": "16:9"
}
```

有效参数计算：

```text
effective = global_generation_defaults
          <- episode.generation_defaults_json
          <- storyboard.generation_overrides_json
```

不得用“把默认值复制到所有行”替代继承模型。现有 `duration`、`video_model`、`video_resolution`、`video_aspect_ratio` 等列在过渡期继续物化有效值，保证旧生成链路、导出和已有查询兼容；写入默认值或覆写后由服务层在同一事务中更新物化值。

### API 合约

- `GET /api/v1/episodes/:id/generation-settings`
  - 返回 `defaults`、各分镜 `overrides`、`effective`、`mode`。
- `PATCH /api/v1/episodes/:id/generation-settings`
  - 更新本集默认；参数 `override_policy=preserve|replace`，默认 `preserve`。
- `PATCH /api/v1/storyboards/:id/generation-settings`
  - `scope=current` 写当前镜头覆写；`scope=episode_default` 更新本集默认。
- `DELETE /api/v1/storyboards/:id/generation-settings/overrides`
  - 恢复继承。

所有路由复用项目登录态和 ownership guard。批量更新必须使用数据库事务，返回受影响镜头数与最新有效参数，前端不能发送 N 个并行单镜请求替代批量 API。

### 兼容迁移

- 已有分镜值与本集项目参数相同：迁移为继承。
- 与本集参数不同：只把不同字段写入 `generation_overrides_json`。
- 没有项目参数：以当前集第一条有效分镜为本集默认，其余差异转为覆写。
- 迁移完成后刷新和后端重启必须得到相同的 `mode/effective`。

## 3.2 `@` 素材选择器：上浮大面板 + 插入幽灵

### 布局

- 使用 `Teleport to="body"`，不参与编辑器文档流，不挤压提示词框。
- 优先浮动在提示词框上方；上方空间不足时才落到下方。
- 宽度取 `clamp(420px, editorWidth, 760px)`，桌面端 2～4 列卡片，面板最高 360px。
- 缩略图建议 112×72 或固定 16:9；名称、类型、是否已选放在图片下方/角标，不让文字挤压图片。
- 支持输入过滤、方向键移动、Enter 选择、Esc 关闭；焦点不离开编辑器。

### 插入定位反馈

弹层打开时同时显示：

- 2px 实色插入光标；
- 光标后的半透明 `@素材名` 幽灵 chip，选择列表项时实时更新；
- 从弹层到光标附近的轻量指向锚点/阴影，不遮挡正文；
- 编辑区其余内容保持可见，背景只做 8%～12% 暗化，不使用全屏遮罩。

点击素材后用同一 `anchorOffset` 完成真实插入，避免视觉位置和实际插入位置分叉。弹层关闭或编辑器滚动、窗口缩放时重新定位。

## 3.3 媒体最优解：图片海报墙 + 单活动播放器

### 海报优先级

每个视频卡片必须始终得到一张图片，按以下顺序：

1. `video_generations.poster_local_path`：完成视频归档后由后台任务用 FFmpeg 提取首个可用非黑帧；
2. 生成请求中的首帧素材或分镜主图/首帧图；
3. 视频素材的 `assets.thumbnail_local_path`；
4. 项目内置、无文字的电影画幅占位图（深色渐变 + 帧线，不出现“点击加载”等文字）。

新增 `video_generations.poster_local_path TEXT`。完成态海报必须是本地持久化路径，不能保存供应商签名 URL。历史视频在读取时只返回 `/static/...` 可恢复海报；旧视频海报采用后台低优先级补齐，禁止在 HTTP handler 中同步跑 FFmpeg。

### 加载与播放

- 镜头列表、历史条、素材卡：仅 `<img loading="lazy" decoding="async">`，不挂载 `<video>`。
- 当前工作区：只保留一个主 `<video preload="metadata" playsinline>`。
- 点击镜头：立即更新海报与视频源，并在本次用户手势链中调用 `load()` + `play()`；播放成功后淡出海报。
- 浏览器若拒绝自动播放：保留海报中央的无文字播放图标，单击继续；不回退成文字占位。
- 切镜前暂停旧视频并清空旧对象引用，避免多路解码；快速连点只执行最后一次切源，前一次用递增 token 作废。
- 历史版本点击同样立即在唯一主播放器中切换并播放。

### 性能预算

- 非活动区域 `<video>` 数量：0；全页活动 `<video>` 数量：项目工作台 1 个，自由创作 1 个。
- 首屏海报并发请求：最多 6 个，其余由 IntersectionObserver 分批加载。
- 镜头点击到海报切换：小于 50ms；点击到 `play()` 调用：同一动画帧内。
- 滚动过程中不创建/销毁媒体解码器。

## 3.4 积分最优解：追加为主、校正为辅、累计独立

### 管理端交互

“调整余额”弹窗改为两个明确模式：

1. `发放/扣减积分`（默认）
   - 输入“变动积分”；正数追加，负数扣减；
   - 实时显示“当前余额 → 调整后余额”；
   - 原因必填，常用原因可选；
   - 产生 `recharge`、`admin_debit` 或 `refund` 等明确流水类型。
2. `余额校正`（高级操作）
   - 输入目标余额；
   - 明确显示系统将写入的差额；
   - 只用于迁移、对账修复、历史数据纠正；
   - 原因必填，并记录 `balance_correction` 审计。

默认页面不再把“直接设置目标余额”作为主按钮。校正不能改写累计真实消费。

### 账号统计口径

账号总览展示：

- 当前余额 `balance_micro`
- 冻结积分 `frozen_micro`
- 可用积分 `balance_micro - frozen_micro`
- 累计发放 `total_granted_micro`
- 累计真实消费 `total_consumed_micro`
- 累计退款/冲正 `total_refunded_micro`
- 净充值/净发放与时间范围消费

现有 `total_recharged_micro` 可兼容映射为累计发放，但建议迁移成更清晰的统计字段或增加分类汇总表。总消费的权威来源是 `settleAuthorization()` 产生的结算流水及 `total_consumed_micro`，不是“历史发放 - 当前余额”，因为冻结、退款、管理员扣减、校正都会破坏该等式。

### API 与账本约束

- `POST /api/v1/admin/users/:id/balance-adjustments`
  - 请求：`{ amount_credits, operation, reason, idempotency_key }`
  - `operation=grant|debit|refund`。
- `POST /api/v1/admin/users/:id/balance-corrections`
  - 请求：`{ target_credits, reason, idempotency_key }`。
- `GET /api/v1/admin/users` 增加累计统计字段。
- 余额变动、账本流水、累计统计、审计记录必须在同一数据库事务内完成。
- 管理写操作增加幂等键，防止双击/网络重试重复发放。
- 任何扣减后余额不得小于冻结金额；退款不得伪装为新充值；校正不计入真实消费。

## 3.5 拖动定位：缓存排版而不是追着鼠标重排

### 算法

拖动开始或以下条件变化时才重建排版缓存：文本、字体、编辑器宽度、滚动位置、缩放比例。

缓存内容：

- 每行的 `top/bottom/startOffset/endOffset`；
- 行内字符边界的 `x/offset`；
- 编辑器相对坐标与滚动偏移。

`dragover` 只做三件事：

1. 保存最新鼠标坐标；
2. 若当前无待执行帧，则申请一次 `requestAnimationFrame`；
3. 在该帧中用二分查找目标行，再查找最近字符边界，使用 `transform: translate3d(...)` 移动插入光标和幽灵 chip。

不得在 `dragover` 中创建镜像、逐字符创建 Range 或反复读写布局。使用 passive-safe 的单一拖动会话，离开编辑器、drop、Esc、窗口失焦时必须清理 RAF 和缓存。

### 体验指标

- 60Hz 显示器下光标延迟不超过 1 帧，长提示词下仍保持至少 55fps。
- 光标必须贴近鼠标所在视觉行，不跨行吸附。
- 自动滚动仅在编辑器上下 24px 热区触发，速度随离边缘距离变化；滚动后增量更新坐标。
- drop 后插入位置与落下前幽灵位置一致，误差不超过一个字符边界。

## 3.6 页面刷新不丢提示词：自动保存 + 草稿恢复

### 覆盖字段

- 项目分镜全能提示词 `universal_segment_text`；
- 项目分镜经典视频提示词 `video_prompt` 与图片提示词 `image_prompt`；
- 自由创作镜头 `prompt`、`prompt_document` 和尚未提交的参数/素材顺序。

### 保存协议

1. 每次输入立即把草稿写入 `localStorage`，键包含登录用户、工作区类型、项目/剧集/镜头 ID，禁止不同账号或镜头互相恢复。
2. 停止输入 500～700ms 后调用项目 HTTP API 自动保存；每镜独立定时器和递增 revision，禁止镜头 A 的定时器把内容写到镜头 B。
3. 失焦、切镜、`visibilitychange=hidden`、`pagehide` 时立即触发保存；页面卸载不把异步请求成功当作可靠保证，本地草稿必须已经落盘。
4. 服务端响应携带保存后的 `updated_at`；只有请求 revision 仍为当前最新版本时才能清理本地草稿，防止旧响应覆盖新输入。
5. 页面加载先取服务端值，再检查同镜头本地草稿：草稿文本不同且 `savedAt` 晚于服务端 `updated_at` 时恢复，并显示“已恢复未保存草稿”；相同或更旧则自动清理。
6. 用户主动清空提示词属于有效内容，必须保存空串/`null`，不能因 falsy 回退到旧提示词。

本地草稿仅保存业务编辑内容，不保存令牌、Cookie、API Key 或供应商签名 URL。草稿保留 7 天并在启动时清理过期记录。

## 五、验收标准

### 分镜参数

1. 新集第一次在任意分镜修改五项参数，其余分镜立即同步。
2. 再次修改某个镜头时只改变该镜头，并显示“当前镜头自定义”。
3. 修改本集默认只更新继承镜头；恢复默认后该镜头重新跟随。
4. 刷新页面、重启后端后继承/覆写状态和有效值不变。

### `@` 引用与拖动

1. `@` 面板优先浮在提示词框上方，不压缩编辑区，1280×720 下至少同时展示 4 个素材。
2. 键盘和鼠标均能选择；插入前有光标和幽灵引用，插入后位置一致。
3. 2,000 字提示词连续拖动 10 秒，光标无明显追赶感，平均帧率不低于 55fps。
4. 中文、换行、滚动后的 drop 均落在预览位置附近。

### 媒体

1. 所有镜头与历史卡片均为图片海报，不出现文字占位镜头。
2. 页面非活动区域没有 `<video>`；活动播放器数量固定为 1。
3. 点击镜头或历史版本后立即切源并开始播放；快速连点最终只播放最后选择项。
4. 视频完成、刷新、重启后海报仍从本地路径恢复；不使用供应商签名 URL 兜底。

### 积分

1. 默认发放 100 积分是在当前余额上追加 100，并生成唯一流水。
2. 双击或重试相同幂等请求不会重复发放。
3. 余额校正单独记录差额与前后值，不改变累计真实消费。
4. 账号总览的累计消费等于结算流水之和，退款、冻结和校正口径清晰可追溯。

### 工程验证

- 后端：`cd backend-node && node --test test/*.test.js`
- 前端：`cd frontweb && node --test test/*.test.js`
- 构建：`cd frontweb && npm run build`
- 浏览器：检查 Console 无新增错误；验证点击切镜、立即播放、`@` 上浮、拖动定位、参数继承与管理员积分预览。

### 提示词刷新恢复

1. 输入提示词后立即刷新，服务端保存已完成时从服务端恢复，未完成时从本地草稿恢复，文字均不丢失。
2. 连续编辑两个镜头后刷新，各镜只恢复自己的内容；不同登录账号不得读取彼此草稿。
3. 清空提示词后刷新仍为空，不回退到旧内容。
4. 模拟保存请求乱序，较旧响应不得清除较新草稿或覆盖当前编辑器。
5. 后端重启后已保存提示词仍可读取；断网草稿在恢复网络后自动补存并清理。

## 六、实施顺序与风险控制

1. 先落参数/积分数据模型、事务 API 和迁移测试。
2. 再实现海报提取后台任务与旧数据异步补齐，确保完成态媒体可恢复。
3. 实现单播放器和图片海报墙，随后处理点击立即播放。
4. 最后重构 `@` 弹层与拖动缓存；用 2,000 字、多行中文和滚动场景做性能验收。
5. 全量测试与 production build 通过后，再用浏览器按验收清单闭环。

风险与回退：

- 参数迁移保留旧物化列，出现问题时可临时按旧列读取，不删除新 JSON 数据。
- 海报任务失败不影响视频完成状态，回退到分镜图或本地无文字占位图。
- 自动播放失败不算生成失败，只保留图片海报和播放图标。
- 积分新接口上线后保留旧 `target_credits` 兼容一个版本，但管理端不再默认调用；审计必须能区分旧设置与新校正。
