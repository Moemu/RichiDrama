# LocalMiniDrama 浅色 / 深色 UI 全量适配与创作体验提升方案

> 日期：2026-08-13
> 状态：已完成
> 适用范围：全部前端路由、Element Plus 基础组件、分镜与全能视频工作台、画布、素材库、AI 工具、AI 配置、账号与管理页面
> 设计依据：项目现有视觉语言、Web UI / WCAG 2.2 规范、真实浏览器浅色与深色截图审计

## 一、目标与完成定义

本次不是给几个深色页面附加零散的 `html.light` 补丁，而是建立一套共享信息层级、在两种主题中具有同等可读性与操作确定性的创作界面。

完成必须同时满足：

1. 全部路由均由语义主题变量控制背景、表面、文字、边框、交互状态和阴影；页面局部硬编码色不能破坏主题。
2. 浅色模式不是简单“背景变白”：要保留舞台感、画布深度、主次操作层级和创作氛围。
3. 深色模式不以纯黑堆叠：相邻区域要通过三层表面、边框与适度高光可辨识。
4. 普通文字对背景尽量达到 WCAG AA 4.5:1，控件边界、焦点环和图形状态至少 3:1。
5. hover 与 keyboard focus 具有等价反馈；焦点环至少 2px，不以颜色作为唯一状态信息。
6. 动效只用于解释状态或层级，尊重 `prefers-reduced-motion`；高对比和强制配色模式仍可操作。
7. 生产构建与现有自动化测试通过，并在内置浏览器逐页完成浅色 / 深色截图及关键交互验收。

## 二、现状审计

### 2.1 结构性根因

- `frontweb/src/styles/theme.css` 已有初步令牌，但全局覆盖与页面内大量硬编码规则竞争；当前约有 1004 处背景、文字或边框硬编码色。
- `FilmCreate.vue`、`FreeCreate.vue`、`FilmList.vue`、`DramaDetail.vue` 分别存在大量自己的浅色补丁，导致选择器优先级升级、同类控件跨页面表现不同。
- AI 工具、文本工作台、媒体工作台、账号和管理页仍以单一深色值书写，浅色主要依赖全局强制覆盖，次级文字和局部表面经常失去层级。
- 画布节点、浮动工具条和属性面板使用各自颜色体系，浅色画布内仍出现深色孤岛。
- HTML 预加载背景与主题令牌不一致，原生控件 `color-scheme` 元信息缺失，可能产生首帧闪烁或滚动条主题漂移。

### 2.2 浏览器基线结论

- 项目工作台：结构基本成立，但浅色大面积暖白相近，快捷入口、项目卡片和页面背景分离度不足。
- 分镜工作台：中央舞台有内容聚焦感，但左侧参数、素材卡、右侧镜头卡的浅色表面不统一，部分深色局部规则仍在抢色。
- AI 工具页：次级说明文字过浅，工具卡输入/产出信息在浅色下接近不可读。
- AI 配置：表格结构清楚，但行 hover、表头、操作链接和状态标签缺少强弱反馈。
- 素材库：大量纯白卡片铺在暖白背景上，缺少 hover、选中和媒体类型层级。
- 画布：浅色网格舒服，但节点、浮条与侧栏存在深色孤岛，视觉语言不连续。

## 三、统一语义令牌

### 3.0 Apple-like 视觉准则

整体采用 Apple-like 的信息纪律与材质逻辑，但不复制系统控件：

- **清晰优先**：内容、媒体和当前任务永远比装饰更突出；标题紧凑，正文有舒适行高，说明文字不靠极低对比度制造“高级感”。
- **克制材质**：实体表面承担长时间阅读；半透明、模糊与高光仅用于顶栏、弹层、悬浮工具条等具有真实空间关系的区域。
- **空间连续性**：卡片、面板和弹层使用统一圆角阶梯（8 / 12 / 16px）、1px 发丝边框和柔和扩散阴影；同层级不随页面改变材质。
- **自然动效**：交互反馈为 160–220ms，主要使用 opacity 与 transform；选中状态不做跳跃式缩放，减少动态偏好下立即停用。
- **精确反馈**：主操作、当前步骤、当前节点、运行状态和错误恢复都明确可见；hover、focus、pressed、disabled 各自可辨。
- **主题等价**：浅色不是深色反相，深色也不是纯黑版本；两者共享层级与交互语义，只调整亮度、材质与阴影参数。

### 3.1 表面层级

| 语义 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg-page` | 柔和冷暖中性画布 | 深蓝黑画布 | 页面最底层 |
| `--bg-surface` | 实体主表面 | 一级表面 | 顶栏、主卡片、面板 |
| `--bg-raised` | 抬升表面 | 二级表面 | 表单、嵌套卡、工具区 |
| `--bg-elevated` | 弹出表面 | 三级表面 | 对话框、菜单、浮层 |
| `--bg-hover` | 轻紫灰 hover | 蓝灰 hover | 可操作项反馈 |
| `--bg-active` | 中等紫灰 active | 高亮蓝灰 | 选中、当前步骤 |

浅色 `--bg-surface` 改为实体颜色；透明玻璃只用于顶栏和明确浮层，避免整页泛白与内容透叠。

### 3.2 文字与边界

- `--text-primary`：标题、主数值、当前操作。
- `--text-regular`：正文与表单值。
- `--text-muted`：说明文字，仍需满足常规字号可读性。
- `--text-faint`：仅用于非关键信息、占位符与禁用态，不承载关键提示。
- `--border-color`：控件边界；`--border-strong`：交互与选中；`--border-subtle`：分组线。
- 新增 `--text-on-accent`、`--status-*`、`--surface-glow`、`--stage-*`，禁止页面自行猜测前景色。

### 3.3 状态和交互

- 主按钮：品牌紫渐变，浅色下使用更深紫保证白字对比。
- 次按钮：实体表面 + 清晰边框；hover 同时改变边框、背景和文字。
- active：边框 + 背景 + 轻量内侧标记，不只改变文字颜色。
- focus-visible：2px 高对比焦点环，偏移 2px；不能以 `outline:none` 结束。
- disabled：保留形状和说明，降低强调但不降到不可读。
- success / warning / danger / info：每类同时具备文字、图标或标签语义。

## 四、分层实施方案

### 4.1 基础层

修改 `theme.css` 与 `index.html`：

1. 重建浅色实体表面、文字和边框令牌；补齐状态、舞台、遮罩、滚动条与焦点令牌。
2. 将 Element Plus 的输入、下拉、表格、对话框、标签、分页、复选框、开关、tooltip、message 映射到语义令牌。
3. 添加 `<meta name="color-scheme" content="light dark">` 与动态 `theme-color`；预加载背景与正式令牌一致。
4. 加入 `prefers-contrast: more`、`forced-colors: active` 和 reduced motion 兜底。
5. 全局交互卡统一 hover / focus-visible / active 反馈，保持 transform/opacity 合成层动画。

### 4.2 应用外壳与内容页面

- 项目列表 / 剧集详情：强化 hero、快捷入口和卡片层级；项目状态与主要行动更醒目。
- 素材库：表面分层、媒体卡 hover/focus、筛选器选中态、批量操作层级统一。
- AI 工具及工作台：修复浅色次级文字；输入、历史、结果三栏使用明确层级；空状态与运行状态具备视觉锚点。
- AI 配置 / 账户 / 后台：表格表头、行 hover、危险操作、数字列与标签状态统一。

### 4.3 创作工作台

- 分镜 / 全能视频：两侧控制台使用实体表面，中央视频舞台保持主题无关的影视暗场；浅色只改变舞台外框与周边控制，不把视频舞台漂白。
- 镜头卡、素材卡、参数块和提示词区统一选中与焦点反馈；可滚动区有轻量边缘提示。
- `@` 虚影浮层在浅色采用高透明实体白 + 紫灰边框，在深色采用深蓝玻璃；两种主题都保持内容可感知但文字清晰。
- 画布：画布本体、节点、连线、浮动工具条和侧栏全部引用画布语义令牌；当前节点与可连接状态清晰区分。

## 五、交互性与视觉冲击力策略

1. **聚焦创作**：视频舞台、画布当前节点、工具结果区成为最高视觉重心；控制面板降低装饰噪音。
2. **行动层级**：每个区域仅一个强主操作；次级和危险操作通过样式层级而非位置猜测区分。
3. **连续反馈**：hover 预告可点击，focus 服务键盘，active 表示位置，loading 立即回应，completed 使用文字与图标双重确认。
4. **适度冲击力**：品牌紫、青色只投放在主操作、流程进度、当前节点和关键数据；不大面积染色。
5. **媒体优先**：素材缩略图和真实视频保持自然色，UI 表面不通过强滤镜破坏创作判断。
6. **长时舒适**：浅色使用柔和中性背景而非纯白；深色避免纯黑与高亮白大面积对撞。

## 八、执行与验收结果

### 8.1 已实施

- 重建浅色实体表面、文字、边框、状态、舞台和遮罩令牌，并与深色保持同一语义契约。
