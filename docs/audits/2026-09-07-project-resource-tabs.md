# 项目详情制作资源修复

原页面用两组同名页签分别读取制作实体和项目库。项目库为空时，左侧页签只显示空状态，容易被理解为页签失效。按用户确认合并为角色、场景、道具、项目素材四个页签。

角色、场景、道具页签同时显示制作条目和项目库条目，保留各自来源标记、编辑接口和库导入入口。项目素材沿用 `/assets?scope=project&drama_id=...`，支持图片、视频、音频筛选、搜索、分页和预览；素材管理入口带项目范围及返回地址。刷新和返回可恢复资源页签。

资源区域改为页面纵向滚动；编辑和导入弹窗限制在视口宽度内。加载失败显示可重试错误，不将失败伪装成空库。媒体查询忽略过期响应，组件卸载时清除搜索定时器。

消费者检查覆盖前端三个 library API、DramaDetail、FilmCreate 资源 composable、FilmList、MediaLibrary、FreeCreate、ToolAssetSelector，以及后端 library/asset 路由、所有权过滤和既有隔离测试。本次只改详情页面和新增媒体展示组件，沿用原响应、鉴权、持久化路径及历史读取机制；没有修改数据库、后端契约、生成或计费行为。现有和新资源均可显示，不迁移、删除或重新生成历史记录。

本地前端测试和 production build 通过。内置浏览器在隔离数据库、存储和禁止外部网络的后端上验收，覆盖 1280×720、1440×900、1920×1080 及 390×844。检查四页签、来源标记、制作/库编辑、导入入口、图片预览、视频就绪、音频播放、搜索无结果、全局素材排除、分页、纵向滚动、底部按钮、管理页往返及刷新恢复。注入 503 后，项目库仍保留制作条目，媒体列表保留已有结果；恢复服务后重试成功。

测试数据仅通过隔离项目 HTTP API 写入；未调用真实供应商或生产 API。最终远端检查以 PR 当前提交记录为准。
