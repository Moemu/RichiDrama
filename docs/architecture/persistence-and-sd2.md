# 媒体持久化、时区与 SD2 认证约束

## 时间

数据库与 API 使用 UTC ISO 8601 时间。前端展示统一使用 `Asia/Shanghai`，不得使用浏览器默认时区。这样本地开发、容器和用户浏览器在不同时区时仍展示同一中国时间。

## 视频持久化不变量

供应商交付 URL（包括火山引擎/TOS 的签名 URL）仅用于下载，不能作为产品完成态的持久地址。`video_generations.status = completed` 必须同时满足：

1. 视频字节已写入本地 storage；
2. `local_path` 是有效的相对存储路径；
3. 对外 `video_url` 是 `/static/<local_path>`。

无法本地归档时，记录必须失败并保留可重试错误；不得将临时 URL 写入视频、素材、Omni 历史、分镜或合成成片。服务启动时需要修正历史上“已完成但无本地路径”的记录。

视频合成也必须产出本地文件。ffmpeg 缺失或合成失败时明确失败，不能回退到第一段供应商视频 URL。

## SD2 无感认证

认证有两段：创建资产通常耗时 1–2 秒，供应商就绪轮询通常耗时 5–30 秒。HTTP 请求只执行创建：先持久化 `seedance2_asset.status = processing`，立即返回；后台 `setImmediate` 轮询后再写入 `active` 或 `failed`。前端在声明真人素材时自动发起认证并轮询刷新。

生成服务仍是最终裁决者：凡声明为真人的图片素材，只有 `active` 的 SD2 资产可被传给 Seedance。前端的自动化不能替代后端校验。
