# 账号密码重置

第一期支持邮件验证码找回和管理员重置。手机号找回尚未启用。

## 配置邮件

通过部署进程的环境变量配置 SMTP。不要把授权码写入仓库或前端。

| 变量 | 含义与默认值 |
| --- | --- |
| `SMTP_HOST` | SMTP 服务器；缺省时关闭邮件功能 |
| `SMTP_PORT` | 端口；隐式 TLS 默认 465，否则默认 587 |
| `SMTP_SECURE` | `true` 使用隐式 TLS；默认 `false` |
| `SMTP_REQUIRE_TLS` | 默认 `true`，要求 STARTTLS；仅隔离的本地邮件测试使用 `false` |
| `SMTP_USER` | 发件账号；无需认证的内部 SMTP relay 可不设置 |
| `SMTP_PASSWORD` | SMTP 密码或授权码 |
| `SMTP_FROM` | 发件地址；缺省时关闭邮件功能 |
| `AUTH_TRUST_PROXY` | 可选的受信任代理 IP、CIDR 或 Express 命名网段，逗号分隔；默认不信任转发头 |

例如，465 端口通常配合 `SMTP_SECURE=true`，587 端口通常配合 `SMTP_SECURE=false` 和 `SMTP_REQUIRE_TLS=true`。配置行为见 [Nodemailer SMTP 文档](https://nodemailer.com/smtp)。系统始终验证 TLS 证书。

反向代理部署必须准确设置受信任代理范围，否则来源 IP 限流会按代理地址统计。不要把任意客户端或全部网段设为受信任代理。

配置只在服务启动时读取。邮件未配置时，页面显示不可用，账号原有登录及管理员重置仍可使用。配置就绪仅表示字段齐全，不保证 SMTP 账号或网络可用。

## 操作流程

1. 用户登录后，在“账户中心 → 账户安全 → 找回密码邮箱”填写邮箱、当前密码和验证码。邮箱验证成功后才生效。
2. 更换邮箱同样需要当前密码与新邮箱验证码。成功前保留原邮箱，成功后旧邮箱的找回验证码失效。
3. 忘记密码时，从登录页进入“忘记密码”，填写已绑定邮箱、验证码和新密码。
4. 管理员在“运营后台 → 设置 → 用户与余额”选择创作账号，点击“重置密码”。界面要求确认目标账号。
5. 管理员复制随机密码与说明，自行发送给用户。系统不会替管理员发送临时密码。

随机密码为 16 位、24 小时有效，只显示一次。用户登录后必须先改密。丢失临时密码或超过有效期时，可再次重置，或通过已绑定邮箱找回。

所有新设置的密码要求 8–128 个字符。旧短密码仍可登录。原有后台 `PATCH /admin/users/:id` 的 `password` 字段仍接受请求，但仅可操作创作账号，并按临时密码处理，要求用户登录后改密。

## HTTP 接口

以下路径均使用 `/api/v1` 前缀，响应沿用项目的 `{ success, data, timestamp }` 格式。

| 方法与路径 | 权限 | 请求或响应 |
| --- | --- | --- |
| `GET /auth/recovery-options` | 无需登录 | `{ email_enabled }` |
| `POST /auth/password-reset/code` | 无需登录 | 请求 `{ email }`；统一提示 |
| `POST /auth/password-reset/confirm` | 无需登录 | `{ email, code, new_password }` |
| `GET /auth/email` | 普通登录态 | `{ email_enabled, email }`；未绑定时邮箱为 `null` |
| `POST /auth/email/code` | 普通登录态 | `{ email, password }` |
| `POST /auth/email/confirm` | 普通登录态 | `{ email, password, code }` |
| `POST /admin/users/:id/reset-password` | 运营管理员 | 请求 `{ confirm: true }`；响应 `{ temporary_password, expires_at }` |
| `POST /auth/change-password` | 普通或临时登录态 | 沿用 `{ old_password, new_password }`；成功后重新登录 |

身份响应增加 `must_change_password`。临时登录态只允许读取身份、建立同一会话 Cookie、修改密码和退出登录；业务接口与受保护媒体均拒绝访问，返回 `403 PASSWORD_CHANGE_REQUIRED`。

密码更新后，旧 JWT、`X-LMD-Session`、Bearer 和 Cookie 会话全部失效。前端清理身份缓存，要求重新登录；其他账号会话不受影响。

## 验证码与审计

- 验证码为六位数字，10 分钟有效，最多验证 5 次，成功后只能消费一次。
- 同一邮箱重发间隔 60 秒，每小时最多 5 次；同一来源 IP 每小时最多 20 次。按绑定、找回两种发送用途合并统计。
- 限流计数包括发送失败和未知邮箱请求。重发会使同用途的旧验证码失效。
- 数据库只保存带服务端密钥的验证码摘要。摘要使用持久的 JWT 签名密钥派生；更换该密钥会使未完成的验证码和旧登录态失效。
- 找回请求立即返回统一提示，不等待 SMTP，也不泄露邮箱是否存在。邮件失败记录在审计中，前端不单独披露该邮箱的发送结果。
- 发送中断不会在重启后自动补发。未完成的验证码保持不可用，用户可在限流允许后重新获取。
- 审计记录操作者、对象、结果和 UTC 时间；后台按北京时间展示。未登录请求使用操作者 `0`，展示为“未登录请求”。验证码和密码不进入日志或审计。

## 历史兼容与验证

迁移 `78_password_recovery.sql` 可由现有迁移执行器重复运行。历史账号的邮箱默认为空，会话版本为 `0`，不强制改密，也不会自动绑定邮箱。无会话版本的旧 JWT 按版本 `0` 校验，账号主动改密后才失效。

新行为只作用于主动绑定、更换邮箱、重置或修改密码的账号。不会改写历史项目、媒体、余额、账本或任务状态，也不会取消已提交任务。

跨组件检查覆盖账号服务、认证中间件、API 路由、后台旧改密入口、受保护静态媒体、前端 API 封装、登录跳转、账户中心、身份缓存、Cookie 恢复和审计列表。

自动化测试使用隔离 SQLite 和只监听 `127.0.0.1` 的本地 SMTP 接收器，不访问真实邮件或 AI 供应商。测试覆盖验证码消费竞争、限流、过期、邮箱更换、管理员权限、旧会话失效、强制改密及迁移/重启读取。
