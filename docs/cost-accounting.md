# 客户与项目消耗报表

分支 `codex/customer-cost-accounting` 依赖 PR #37 的供应商连接、模型目录和价目版本能力。PR #38 保持草稿，预览部署不代表生产发布。

## 使用方式

运营工作台 → 消耗与成本（`/admin/costs`）。选择日期、客户或项目后直接查询，查看原用量、计价明细和原扣费。无需创建成本账号、再选 IAM 配置、手写成本规则、历史补录或批量估算。

模型定价继续使用原运营工作台的价目表和 `providerPriceService`。该服务负责复用 IAM 配置、同步、解析复杂规格、审核与发布。成本页面不发起价格同步或供应商请求，不维护第二套模型规则。

## 三种金额

| 字段 | 含义 |
| --- | --- |
| 模型计价折合 | 原实际用量按调用时的价格快照计算，按 100 积分 = 1 元折合。直接复用 `billingService.snapshotCalculation`，包含原规格、实际用量阶梯、图片免费数量及整数舍入。 |
| 供应商费率估算 | 上述计算中带火山官方文档、原产品页（`/product/yunque`、`/product/doubao/`）或 `ListModelActivations` 同步来源、标记 CNY 的价格。它是有来源的模型费率估算，不是实付账单。自定义价目和平台免费项不纳入该指标。 |
| 原平台扣费 | 直接读取用量日志的 `charged_micro`，其中已经包含原系统的关联补扣。明细另列原扣费和补扣，不重复相加。 |

明细逐项展示实际数量、计费数量、适用单位价格、单位数量、规格、价目版本、来源和小计。差额是原扣费减去原价复算值。差异只作展示，不扣款、不修改余额。原成本规则修订保留在附属证据中，其金额不混入原价口径。

费率来源字段是原模型价目保存的来源。它不证明资源包、代金券、返款、账号实付或组织账单中的平台归属。本功能未导入或分摊供应商账单，也不声称还原历史每次重试的实付费用。

## 记录与时间

新增只读 API：`GET /api/v1/admin/costs/activity`、`GET /api/v1/admin/costs/activity/:id`。沿用运营后台鉴权，普通用户和客户管理员不能访问。

- 已结算业务直接读取 `billing_usage_logs`，优先使用日志实际用量，缺失时读取关联结算快照的 `actual_usage`。不会用预授权预估用量补齐实际消耗。
- 未结算预授权也可见。使用已持久化的待对账用量或调用观察证据；没有实际用量就显示缺用量。已释放且无用量的预授权单列，不计入缺用量或计价覆盖分母。
- 同一业务的重试、历史补录作为附属证据，不再增加业务记录数和重复用量。没有账本关联的独立实时调用仍可见，缺少原价依据时不猜金额。
- 客户、项目与用户身份使用原账本及历史快照。不会按用户当前成员关系改写个人或客户归属。已有 AI 配置关联从调用记录读取；历史未保存的连接不猜测、不要求补建供应商账号。
- 已结算记录按结算时间筛选；未结算按预授权时间，独立调用按提交时间。未结算业务完成后可能移动日期。页面所有汇总、分组和原扣费使用同一组记录及筛选条件。
- 时间存储和传输沿用 UTC ISO，页面、分组与 CSV 明确使用 `Asia/Shanghai`。费用或实际用量发生冲突时保留冲突依据，冲突用量与估算不纳入汇总。

筛选支持日期、客户、项目、用户、模型、操作和计价状态。按客户、项目、用户、模型、操作、小时、日、月分组。每页 20 条，但汇总和月报不受旧补录批次的 1000 条限制。读取流式遍历记录，月报按 500 条分批保存；金额超出安全整数范围时报错，避免静默失真。

## 月报与兼容边界

新月报通过已有 `POST /reports` 传入 `basis: billing_activity_v1`。保存时固定汇总、每条实际用量、价格明细及扣费。CSV 包含口径、价格来源和完整明细，采用分批读取与流式下载。下载期间不持有活动 SQLite 迭代器阻止其他写入。

旧客户端不传 `basis` 时保持原月报语义。原 `summary`、`calls`、`breakdown`、价格、账号、补录、修订 API 仍保持兼容；新页面不调用其配置和补算功能。旧月报显示原口径提示，并仍可按原值读取和导出。

新行为启用范围：所有记录均可通过新增只读接口查询；只有显式保存的新月报使用新口径。历史扣费、任务、价格、成本修订和旧月报全部排除自动重写。查询不创建成本记录，不触发后台生成，不重复提交供应商或扣费。

新迁移 `20260909_cost_activity_indexes.sql` 仅新增账本关联与时间查询索引，可重复执行。此前成本表迁移仍保留，以支持已有审计数据；没有删除或改写业务数据的迁移。
