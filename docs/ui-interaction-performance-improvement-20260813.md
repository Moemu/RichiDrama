# UI、交互与视频渲染闭环改进方案（2026-08-13）

## 目标与优先级

本轮保持业务功能、线上 API 与计费链路不变，只优化前端呈现和交互。视觉优先级固定为：

1. T0：提示词编辑与生成参数，必须始终清晰、可操作。
2. T1：当前成片播放器与生成状态。
3. T2：镜头列表、素材列表和历史版本，尺寸适中并可滚动，不抢占 T0 空间。

## 现状证据

- 线上 `test/test`、1280×720 实测：自由创作右栏约 320px，参数说明、素材提示、状态文字大量使用 10–11px 字号，暗色背景下需要费力辨认。
- 自由创作同一个成片同时挂载在镜头卡、主播放器和历史版本三个 `<video>`；历史版本使用 `preload="auto"`，打开页面即主动加载视频字节。
- 项目分镜页对每条分镜都挂载主视频及全部历史视频的 `<video preload="metadata">`。分镜较多时会并发发起大量 Range/metadata 请求并创建媒体解码上下文。
- `OmniAssetPromptEditor` 的拖入逻辑固定传入 `append: true`，素材只能追加到末尾；`UniversalSegmentOmniAtEditor` 也只把素材交给父组件做末尾追加。
- 自由创作镜头列表虽有 `overflow:auto`，但没有明确的滚轮切镜行为和操作提示；短列表时滚轮没有可感知反馈。
- 首轮 Console 未发现 error/warning；页面与业务接口可正常返回，问题主要是呈现、交互和媒体加载策略。

## 实施方案

### 1. 字体与视觉层级

- 自由创作正文最低 14px，辅助信息最低 12px，关键标签/表单统一 13–14px，行高不低于 1.45。
- T0 右栏桌面宽度提高到约 360px；镜头栏控制在约 240px；中间播放器弹性占满剩余空间。
- T0 参数卡、提示词、生成按钮保持明显分组；镜头和历史缩略内容降噪但按钮点击区域不小于 30px。
- 仅调整局部尺寸与对比度，不改变既有深浅主题和全局设计语言。

### 2. 镜头滚轮切换

- 鼠标位于镜头列表时：列表可滚动则保持自然滚动；列表无可滚动余量时，滚轮向下/向上切换下一镜/上一镜。
- 增加“滚轮切镜”可见提示；切换后活动镜头自动滚入可见区域。
- 对触控板连续事件做节流，避免一次滚动跨越多个镜头；输入框、选择器等交互区域不拦截滚轮。

### 3. @ 引用按插入点落位

- 普通 textarea：根据拖放坐标计算字符插入点；无法计算时使用拖动前保存的光标位置，最后才回退到文本末尾。
- 项目 contenteditable：根据拖放坐标恢复 DOM Range，新增素材后把对应 `@图片N` 插入该 Range，而不是追加到末尾。
- 键盘输入 `@` 在文章中间选择素材的现有行为继续保留。
- 插入后光标停在引用之后，引用关系与已选素材同步更新。

### 4. 视频渲染性能

- 列表和历史记录不再直接挂载视频播放器：有封面图时展示封面；无封面时展示轻量视频占位图标和状态。
- 只有当前主播放器挂载 `<video>`，设置 `preload="metadata"`，不自动播放，避免打开项目时抢占网络与解码资源。
- 项目分镜页仅活动分镜挂载主播放器；非活动分镜显示“点击加载预览”的轻量占位。视频历史条不挂载 `<video>`。
- 切换活动分镜后再加载对应媒体，保持所有下载、生成、历史切换功能不变。

## 影响面

- 前端：`FreeCreate.vue`、`OmniAssetPromptEditor.vue`、`UniversalSegmentOmniAtEditor.vue`、`FilmCreate.vue`，以及针对纯函数/交互契约的前端测试。
- 后端与 API：不修改接口合约、鉴权、计费、归档、OSS 或 SD2 链路。
- 媒体持久化：继续只使用项目 `/static/...` 本地/OSS 兜底地址，不引入供应商临时 URL。

## 验收标准

1. 1280×720 与更宽桌面下，提示词、参数和生成按钮无需横向滚动即可操作；正文与辅助字清晰可辨。
2. 自由创作至少 3 个镜头时，镜头区滚轮能逐镜切换且不会一次跳多镜。
3. 将素材拖到句子中间，引用出现在落点附近；键盘在句中输入 `@` 选择素材也正确。
4. 打开含视频项目后，DOM 中视频播放器数量与当前活动预览数量一致，不再随分镜数/历史数线性增长。
5. Console 无新增 error；关键 API 返回 2xx，视频 `/static` 请求只在激活预览后发生。
6. 前端测试、后端测试和前端 production build 全部通过；使用 computer use 完成实际滚轮、拖放、页面切换验收。

## 2026-08-13 精确拖放、表现力与日志分页补充

### 精确拖放

原生 textarea 不提供可靠的“拖放坐标 → selectionStart”映射，旧方案只能依赖拖动前光标或近似字符距离。新的交互以 textarea 同字体、行高、内边距、滚动位置构造镜像排版，将鼠标位置映射到同一视觉行的字符边界，并在拖动过程中显示实时紫色插入光标。用户在松手前即可确认引用会落在哪两个字符之间；坐标不可用时才回退到最近一次真实光标。

保留三个无需精细鼠标定位的路径：先点击目标位置再点素材卡“插入此处”（使用已保存的原生 selection offset）；在目标位置输入 `@` 后选择素材；或直接键入完整 `@别名`。拖放是快捷方式，不是唯一入口，触控板或浏览器对 HTML5 拖放支持不稳定时优先使用“插入此处”。

### 当前项目 UI 最优解

当前最优方向仍是“电影工作台”，不继续叠加全屏粒子、频繁光晕、卡片入场或循环视差。短剧工具需要长时间编辑，高密度控制比展示型官网更重；过多特效会降低提示词、参数和任务状态的扫描效率，也会放大 Element Plus 的组件拼接感。

表现力只投入到四个有业务因果的位置：

1. 素材拖入时的实时插入光标和目标反馈。
2. 生成任务 processing 阶段的低频状态呼吸与明确阶段文案。
3. 镜头切换、成片版本切换时 160–220ms 的淡入/位移连续性。
4. 时间线进度、素材选中和任务完成使用统一的紫/青/暖橙状态语言。

其它区域保持稳定、安静和可预测；所有循环动效继续服从 `prefers-reduced-motion`，透明材质服从减少透明度设置。

### 日志分页

资金流水、模型用量、审计日志和个人账单改为服务端分页。API 统一接受 `page`、`page_size`（默认 20，范围 10–100），返回 `{ items, total, page, page_size }`；排序增加 rowid 次级键，保证相同时间戳下翻页稳定。前端页码切换重新请求服务端，所有可见时间继续显式按 `Asia/Shanghai` 格式化。
