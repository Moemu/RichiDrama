# RichiDrama 现代创作产品 UI 方案（2026-08-13）

## 1. 产品定位

RichiDrama 的界面定位为“面向创作者的 AI 影像工作室”，不是数据管理后台。界面应让用户先看到作品、提示词、生成参数与当前进度，再看到配置、账户、删除等管理动作。

设计关键词：电影画布、专注创作、轻量控制、可信进度、克制的未来感。

## 2. 实测问题

### 亮色

- 冷白背景、纯白卡片和紫色主按钮形成典型后台模板观感，缺少创作产品的温度。
- 顶部十余个等权按钮把素材、工具、配置、账户和主要创作动作混在同一层级。
- “快速开始、常用入口、项目”三张卡片面积、边框和语气相近，没有主次焦点。
- 页面大面积留白没有形成舞台或画布，只显得内容稀疏。

### 暗色

- 页面、卡片、表单、侧栏集中在相近灰阶，只靠边框分隔，整体扁平。
- 主按钮是白色，虽然对比充足，但没有产品识别度，也无法表达生成中的能量感。
- 创作工作台三栏都是同一类深灰面板，预览舞台、素材列表和参数控制没有明确角色。
- 小型控件密集排列，视觉上接近工程控制台。

## 3. 视觉系统

### 3.1 颜色

两套主题使用同一品牌色语义，不做互相割裂的两套产品。

| 角色 | 暗色主题 | 亮色主题 | 用途 |
|---|---|---|---|
| 页面 | `#080B12` 深墨蓝 | `#F4F1EB` 暖灰画布 | 全局背景 |
| 表面 | `#101722` | `rgba(255,255,255,.78)` | 卡片、侧栏 |
| 抬升表面 | `#172131` | `#FFFFFF` | 表单、弹层、聚焦区域 |
| 主文字 | `#F4F6FB` | `#192033` | 标题与关键值 |
| 次文字 | `#A7B0C2` | `#667085` | 说明与元数据 |
| 品牌主色 | `#8B7CFF` | `#6757D9` | 主按钮、选中态、焦点 |
| 能力强调 | `#42D3C7` | `#087F78` | 素材、完成态、连接关系 |
| 生成强调 | `#FFB86B` | `#B65D19` | 生成、耗时、提醒 |

原则：品牌渐变只出现在主要创作动作、品牌标记和聚焦光晕；普通卡片不铺渐变，避免廉价霓虹感。

### 3.2 层级与空间

- L0 画布：带轻微径向光晕或颗粒感，不使用纯色大底。
- L1 导航与侧栏：半透明表面，靠色调与模糊形成连续产品外壳。
- L2 内容卡片：低对比边框、柔和阴影，悬停只抬升 2px。
- L3 聚焦区：提示词、参数、当前成片和主要按钮使用清晰焦点环。
- L4 弹层：明显抬升和背景遮罩，保持内容可读。

### 3.3 字体

- 中文优先 `HarmonyOS Sans SC`、`MiSans`、`PingFang SC`，系统字体兜底；不依赖在线字体。
- 页面标题 28–32px，模块标题 18–20px，正文 14–15px，辅助信息不低于 12px。
- 英文 kicker 只作为品牌节奏，不承担核心信息；使用较宽字距和品牌色。
- 数字、时长、比例使用等宽数字特性，便于扫描。

### 3.4 动效

- 普通反馈 160ms，面板切换 220ms，生成状态可使用低频呼吸光。
- 禁止大面积循环动画；支持 `prefers-reduced-motion`。
- 卡片悬停、按钮按下和镜头切换都提供一致的位移与焦点反馈。

## 4. 产品结构

### 首页

- 顶部从“按钮集合”改为产品导航：左侧品牌；中间为素材与创作入口；右侧只保留主题、配置、账户和主创作按钮。
- 首页头部使用“继续创作”叙事，项目数量为次要信息。
- 快速开始升级为品牌主卡，强调“从想法到成片”；常用入口压缩为工具带。
- 项目卡增加封面舞台或抽象影像占位、最近编辑状态和清晰的继续入口，删除操作默认降噪。

### 自由创作 / 项目分镜

- 左栏定义为“镜头轨道”：更接近时间线，当前镜头使用品牌色轨道标记。
- 中栏定义为“放映舞台”：使用接近黑场的背景，当前成片与提示词形成上下连续创作区。
- 右栏定义为“导演控制台”：T0 的生成方式、按钮、提示词参数拥有最高对比；说明文字、素材管理和高级配置降到次级表面。
- T0 提示词与参数不因视觉升级缩小；右栏保持可点击尺寸和独立滚动。

### 素材库与工具

- 素材优先展示内容缩略图，筛选器表现为轻量胶囊工具条。
- 空状态提供具体创作下一步，不显示后台式占位表格。
- 配置、计费和账户继续使用高密度信息布局，但作为“设置空间”，不反向影响创作页语言。

## 5. 实施顺序

1. 重建全局主题 token、Element Plus 控件状态和光影层级。
2. 重塑首页导航、标题区、快速开始、常用入口和项目卡。
3. 重塑自由创作三栏的轨道、舞台、控制台角色。
4. 将同一视觉语言扩展到项目分镜、素材库和工具页。
5. 用 Codex 内置浏览器 + Computer Use 检查亮/暗主题、1280×720、滚动、弹层、提示词、参数和生成按钮。

## 6. 验收标准

- 亮色不再是冷白后台：暖灰画布、半透明白表面和统一品牌色能够形成连续产品感。
- 暗色至少有页面、侧栏、卡片、抬升控件、黑场舞台五个可感知层级。
- 首页第一眼能区分“继续创作”“新建项目”“素材/工具”“设置”四级重要性。
- 创作页第一眼能区分镜头轨道、成片舞台、提示词和生成参数；T0 区域无横向滚动且按钮可点击。
- 两套主题的功能、尺寸和状态语义一致；切换主题不会出现局部旧配色。
- Console 无新增错误，关键 API 返回 2xx；前端测试、后端测试和 production build 通过。

## 7. 2026-08-13 结构复核与重构契约

### 7.1 自由创作提示词重复

源码确认同一 `prompt` 同时绑定到两个 `OmniAssetPromptEditor`：中间“本分镜脚本”固定出现，非项目自由创作又在右栏出现一次。这两个输入没有业务语义差异，属于重复视图，会造成“到底在哪里输入”的认知负担。

处理契约：

- 每个镜头只保留一个提示词编辑器，固定置于中央舞台下方，形成“预览 → 时间 → 提示词”的连续创作路径。
- 右栏只承担生成方式、生成动作、T0 参数、素材和版本管理，不再复制提示词。
- 提示词仍使用原来的 `prompt`、`promptDocument` 和 `@` 引用逻辑，不改变 API 请求或持久化字段。
- 中央标题由泛化的“本分镜脚本”改为明确的“镜头提示词”，并提示可输入或拖入 `@` 素材。

### 7.2 顶部导航覆盖

现状把素材、工具、删除项目、主题、配置、账户、退出、导入和新建放在一条固定高度的按钮流中，并依赖横向 `overflow`。这会在常见的 1024–1280 宽度出现压缩、裁切或组件覆盖。

处理契约：

- 顶栏只保留三层：品牌；主产品导航；账户/主题与一个主创作动作。
- 素材角色/场景/道具合并为一个“素材”入口组；低频的已删除项目、AI 配置、账户、退出收进“更多”菜单。
- 所有收起操作必须仍可达，不能通过 `display:none` 直接丢失功能。
- 宽度不足时先收起文字导航，再让操作进入菜单；品牌和主创作按钮不覆盖、不换到内容上方。
- 自由创作顶栏左右区域使用 `minmax(0,1fr)`、明确收缩顺序和可达的紧凑操作，禁止依赖横向滚动隐藏按钮。

### 7.3 Apple-like 双主题原则

这里的 Apple-like 不指复制 macOS 控件，而是遵循以下产品原则：

1. 内容优先：画面、提示词、当前镜头和生成动作高于配置外壳。
2. 材质分层：通过半透明表面、柔和阴影、空间间距区分层级，不使用密集边框模拟表格。
3. 克制色彩：大面积使用中性色；品牌紫只标记主动作/选中态，青色表示素材/完成，暖橙表示生成/提醒。
4. 排版清晰：同一语义只出现一次；标题、正文、辅助文字形成稳定字号和对比度阶梯。
5. 动效有因：只在悬停、切换、生成状态中反馈，不加入装饰性循环动画。

### 7.4 样式三层架构

- 第一层 `theme.css`：只定义颜色、字号、圆角、阴影、焦点和 Element Plus 基础状态。
- 第二层产品组件：导航、卡片、输入、弹层按 token 着色，不写具体主题色。
- 第三层页面角色：镜头轨道、放映舞台、导演控制台只定义布局和必要的角色差异。

禁止继续增加无主题前缀的深色 `!important`。必须使用亮/暗 token；确需兼容旧规则时，覆盖集中放在全局兼容区，并在选择器中显式包含 `html.light` 或 `html.dark`。

### 7.5 新增验收项

- 非项目自由创作 DOM 中只存在一个提示词编辑器和一个可编辑 `textarea`。
- 1024、1280、1440 宽度下，首页顶栏无重叠；全部低频操作能从“更多”菜单访问。
- 亮色主题下提示词、模型选择、参数说明、禁用按钮和标签文字均达到可辨识对比，不出现深色局部组件拼接。
- 暗色主题保持舞台黑场，但输入、侧栏和卡片至少有三个可辨识表面层级。

### 7.6 亮色模式反差约束

亮色模式不允许用大面积纯黑区块直接嵌入白色或暖灰页面。空视频舞台、镜头占位、历史占位和编辑器必须使用连续的暖灰—雾紫明度阶梯；真实视频播放时可以由媒体本身呈现黑色内容或黑边，但产品 UI 不主动制造黑色矩形。

- 亮色页面背景、侧栏、卡片、输入、空舞台依次使用相邻表面色，避免从 `#FFFFFF` 跳到 `#000000`。
- 空舞台文字使用深灰蓝，播放按钮使用品牌紫；时间线使用紫到青的轻量渐变。
- 亮色镜头缩略图和历史占位使用雾紫灰，图标与文字达到清晰对比但不使用纯黑。
- 禁用状态不得通过极低透明度导致文字消失；使用稳定的次级文字色和较弱表面色表达不可用。

## 8. Apple HIG / Web skill 复核（GitHub）

本轮采用 GitHub 开源项目 `ehmo/platform-design-skills` 中的 `macos-design-guidelines` 与 `web-design-guidelines` 复核。这里借用的是 Apple 的交互原则与桌面产品秩序，不把 Web 页面伪装成 macOS，也不照搬交通灯、原生菜单栏或 SF Symbols。

- 稳定命令记忆：常用动作留在工具栏，低频动作进入可命名的“更多”菜单；窄屏隐藏的动作必须在菜单中保留等价入口。
- 可调整窗口：不设置固定桌面宽度；在 1024–1440px 保持三栏角色，在更窄宽度明确重排，禁止通过页面横向滚动隐藏命令。
- 指针与键盘并重：交互元素有 hover 和 `:focus-visible`，图标按钮具备可访问名称，镜头列表支持键盘聚焦与滚轮切换。
- 语义主题：颜色通过 CSS token 和 Element Plus token 映射；亮暗主题保持相同状态语义，并响应 `prefers-contrast` 与 `prefers-reduced-transparency`。
- 内容让位原则：半透明、阴影和渐变只用于层级提示；用户要求提高对比度或减少透明度时，表面回退为实色、边框与焦点环增强。
